大模型位置编码的原理与实现

从正弦编码到 RoPE —— 让 Transformer 理解"顺序"的关键技术
Sinusoidal PE Learned PE RoPE ALiBi 长度外推 YaRN / NTK-Aware

引言：为什么 Transformer 需要位置编码？

Transformer 的自注意力机制有一个根本性的"缺陷"：它是置换不变的 （permutation invariant）。对于输入序列中的任意两个 token，注意力只计算它们 内容的相似度，完全不考虑它们的位置。

图 1："cat eats fish" 和 "fish eats cat" 意义完全不同， 但没有位置编码时，Attention 计算的分数完全相同。
核心问题：如果不引入位置信息，"猫吃鱼"和"鱼吃猫"对模型来说 是完全等价的——它们包含相同的 token 集合，注意力得分矩阵完全相同。 语言是有序的，位置编码就是告诉模型"谁在前面、谁在后面"的机制。

本文将系统介绍五种主要的位置编码方案，按照发展脉络逐步深入：

2017 — Transformer 原作

正弦位置编码（Sinusoidal PE）

用固定的正弦/余弦函数生成位置向量，加到词嵌入上。优雅但有局限。

2018-2019 — BERT / GPT-2

可学习位置编码（Learned PE）

将位置向量作为可训练参数，简单直接但无法泛化到训练之外的长度。

2021 — RoFormer / LLaMA

旋转位置编码（RoPE）

通过旋转 Q/K 向量编码相对位置，成为当前 LLM 的主流选择。

2022 — BLOOM

ALiBi（线性注意力偏置）

不修改嵌入，直接在注意力分数上加线性偏置，天然支持长度外推。

2023 — 长上下文时代

YaRN / NTK-Aware 扩展

改进 RoPE 的频率分配，将上下文窗口从 4K 扩展到 128K+。

一、正弦位置编码（Sinusoidal PE）

1.1 数学定义

原始 Transformer（Vaswani et al., 2017）提出的位置编码使用不同频率的正弦和余弦函数：

PE(pos, 2i) = sin(pos / 100002i/d)
PE(pos, 2i+1) = cos(pos / 100002i/d)

其中 pos 是位置索引，i 是维度索引，d 是模型维度。偶数维度用 sin，奇数维度用 cos。

1.2 直觉理解

可以把每个位置想象成一个"多刻度时钟"：

  • 低维度（i 小）：频率高，像秒针——相邻位置之间变化剧烈，编码精细的局部位置
  • 高维度（i 大）：频率低，像时针——需要跨越很多位置才会有明显变化，编码粗略的全局位置
  • 合在一起：就像用"时:分:秒"三个刻度唯一标识一个时间点一样，不同频率的组合唯一标识每个位置
图 2：正弦位置编码的可视化。左图：热力图显示不同位置和维度的编码值， 低维度变化快、高维度变化慢。右图：四个不同维度的编码值随位置的变化曲线。

1.3 为什么选择正弦函数？

Vaswani 等人选择正弦函数有一个深刻的数学原因：

线性变换性质：对于任意固定的偏移 k，PE(pos+k) 可以表示为 PE(pos) 的线性变换。 即存在一个只依赖于 k（不依赖于 pos）的矩阵 Mk，使得 PE(pos+k) = Mk · PE(pos)。 这意味着模型理论上可以通过学习来"关注相对位置"。

证明很简洁，基于三角恒等式：

sin(pos+k) = sin(pos)cos(k) + cos(pos)sin(k)
cos(pos+k) = cos(pos)cos(k) - sin(pos)sin(k)

这正好可以写成一个 2×2 旋转矩阵乘以 [sin(pos), cos(pos)]T。

1.4 使用方式

正弦 PE 通过加法注入：将位置编码向量直接加到 token 的词嵌入上：

xi = Embedding(tokeni) + PE(i)

✓ 优点

  • 无需训练，参数量为零
  • 理论上支持任意长度（函数可计算任意 pos）
  • 数学性质优美（线性变换 → 可学习相对位置）
  • 不同位置的 PE 向量两两正交（近似）

✗ 缺点

  • 实际长度外推效果有限（未在长序列上训练过）
  • 加法注入会"污染"词嵌入空间
  • 绝对位置编码——位置 0 和位置 100 的 PE 差异与位置 500 和位置 600 的不同
  • 已被现代 LLM 淘汰

二、可学习位置编码（Learned PE）

2.1 定义

最简单的思路：为每个位置分配一个可训练的参数向量，让模型自己学习 什么样的位置表示最有效。

PE = nn.Embedding(max_len, d_model)

xi = TokenEmbed(tokeni) + PE(i)

实现上就是一个额外的 Embedding 查表操作。代表模型：BERT（512 位置）、 GPT-2（1024 位置）。

2.2 直觉与局限

可学习 PE 的优势是极其灵活——模型可以学到任何位置模式。 但最大的致命缺陷也很明显：

硬长度限制：如果训练时 max_len = 512，推理时遇到第 513 个 token， 对应的位置嵌入根本不存在（没有这一行参数）。 模型无法处理超过训练长度的序列，完全没有外推能力。
图 3：绝对位置编码（左）vs 相对位置编码（右）。绝对编码为每个位置赋予固定标签； 相对编码只关心 token 之间的距离，更符合语言理解的本质。

✓ 优点

  • 实现极简（一行代码）
  • 极度灵活，可学到任意模式
  • 在训练长度内表现良好

✗ 缺点

  • 零外推能力：无法处理训练长度之外的位置
  • 额外参数量（max_len × d_model）
  • 绝对位置——不直接建模相对关系

三、旋转位置编码（RoPE）—— 详细原理

RoPE（Rotary Position Embedding，Su et al., 2021）是当前大语言模型中 最广泛使用的位置编码方案，被 LLaMA、Mistral、Qwen、Gemma 等主流模型采用。

3.1 核心思想：用"旋转"编码位置

RoPE 的核心洞察极为优雅：不在嵌入上加位置信息，而是在 Q 和 K 上做位置相关的旋转。

关键性质：如果我们将位置 i 处的 Q 向量旋转角度 i·θ， 位置 j 处的 K 向量旋转角度 j·θ，那么 Qi · Kj 的点积只取决于 (i - j) · θ——即只取决于相对距离 i-j。 这就是 RoPE 编码相对位置的数学本质。

3.2 二维旋转的直觉

先从最简单的二维情况理解。假设 Q 和 K 各只有 2 个分量 (q0, q1)， RoPE 对这对分量做一个旋转：

RoPE(q, pos) = R(θ · pos) · q

其中 R(α) = [ cosα -sinα ]
                 [ sinα cosα ]

就像时钟的指针一样：位置 0 不旋转，位置 1 旋转 θ 角，位置 2 旋转 2θ 角……

图 4：RoPE 的三视角可视化。
左：同一向量在不同位置被旋转不同角度； 中：Q(pos=5) 与各位置 K 的点积只取决于相对距离； 右：高维 RoPE 的多频率旋转——低维度转得快（精细位置），高维度转得慢（粗略位置）。

3.3 高维扩展

在高维空间（如 d=128），RoPE 将向量两两配对： (q0, q1)、(q2, q3)、...、(q126, q127)， 共 64 对。每对使用不同的频率进行独立旋转：

θm = 1 / 100002m/d     m = 0, 1, 2, ..., d/2-1
  • m=0：θ0 = 1（最高频率），每个位置旋转 1 弧度 —— 编码精细的局部位置
  • m=63：θ63 = 1/10000 ≈ 0.0001（最低频率），几千个位置才转一圈 —— 编码粗略的全局位置
图 5：RoPE 的实现流程。输入经过线性投影得到 Q/K 后，将向量分成 2D 对， 每对以不同频率旋转，旋转角度与位置成正比。关键性质：Q·K 的点积只取决于相对位置差。

3.4 数学证明：为什么只取决于相对位置

核心推导只需一步：

QiT Kj = (R(θ·i) · q)T (R(θ·j) · k) = qT R(θ·i)T R(θ·j) k = qT R(θ·(j - i)) k

最后一步利用了旋转矩阵的性质：R(α)T R(β) = R(β - α)。 这证明了点积只取决于相对距离 (j - i)。

3.5 PyTorch 实现

import torch def precompute_freqs(dim, max_len, base=10000.0): # 计算每对维度的频率 freqs = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim)) # 生成位置 × 频率 的角度矩阵 t = torch.arange(max_len) angles = torch.outer(t, freqs) # [max_len, dim/2] # 返回 cos 和 sin return torch.cos(angles), torch.sin(angles) def apply_rope(x, cos, sin): # x: [batch, seq_len, n_heads, dim] # 将 x 拆成相邻对: (x0,x1), (x2,x3), ... x_even = x[..., 0::2] # 偶数维 x_odd = x[..., 1::2] # 奇数维 # 2D 旋转: [cos -sin] [x_even] # [sin cos] [x_odd ] out_even = x_even * cos - x_odd * sin out_odd = x_even * sin + x_odd * cos # 交错合并回原始形状 return torch.stack([out_even, out_odd], dim=-1).flatten(-2)
实现的优雅性：RoPE 不需要额外的参数（频率是固定公式），不需要修改模型结构 （只在 Attention 的 Q、K 上操作），且可以高效地用逐元素乘法实现（无需构造完整的旋转矩阵）， 计算开销几乎可以忽略。

✓ 优点

  • 天然相对位置：数学上保证只编码相对距离
  • 零额外参数：频率由公式确定
  • 不污染嵌入空间：只作用于 Q/K，不修改 token embedding
  • 远程衰减：距离越远的 token 对，注意力自然衰减
  • 高效实现：逐元素乘法，几乎无额外开销

✗ 缺点

  • 外推有限：虽然优于绝对 PE，但直接外推到远超训练长度时仍会退化
  • 固定基频：base=10000 在所有场景下未必最优
  • 需要扩展技术：超长上下文需要配合 NTK-Aware / YaRN 等修改

四、ALiBi（Attention with Linear Biases）

4.1 核心思想

ALiBi（Press et al., 2022）的思路截然不同：完全不修改嵌入或 Q/K 向量， 而是直接在注意力分数上加一个与距离成正比的负偏置。

Attention(Q, K, V) = Softmax(Q · KT / √dk - m · |i - j|) · V

其中 m 是每个注意力头特有的斜率（slope），|i - j| 是 query 位置 i 和 key 位置 j 之间的距离。

直觉理解：ALiBi 就是在告诉模型： "距离越远的 token，你应该给予越少的关注。" 偏置值随距离线性增长（取负值），距离越远，注意力分数被压得越低。 不同的头有不同的斜率——有的头"近视"（斜率大，只关注近处），有的头"远视"（斜率小，能关注远处）。
图 6：ALiBi 的可视化。左图：单个头的偏置矩阵（斜率 m=0.25）， 距离越远偏置越大（颜色越深，值越负）。右图：不同头使用不同斜率，从 m=1（强近视）到 m=0.0625（弱远视）。

4.2 斜率设定

ALiBi 不需要训练斜率——使用一个固定的几何级数： 对于 h 个注意力头，斜率为 2-8/h, 2-16/h, ..., 2-8。 例如 8 个头的斜率为：1/2, 1/4, 1/8, 1/16, 1/32, 1/64, 1/128, 1/256。

4.3 长度外推能力

ALiBi 的最大优势是天然的长度外推能力。因为偏置公式 -m·|i-j| 对任何距离都有定义，不存在"超出训练范围"的问题。实验表明，在 1024 token 上训练的 ALiBi 模型 可以在 2048 甚至更长的序列上保持良好性能。

✓ 优点

  • 出色的外推能力：无需任何修改即可处理更长序列
  • 极简实现：只需在注意力分数上加一个预计算矩阵
  • 零额外参数：斜率是固定公式
  • 不修改嵌入：与 Embedding 层完全解耦

✗ 缺点

  • 线性偏置可能过于简单，表达力有限
  • 强制"近处重要"的先验不适用于所有任务
  • 在训练长度内的性能通常略逊于 RoPE
  • 未被 LLaMA / GPT 等主流模型采用（BLOOM 使用）

五、长度外推：从 4K 到 128K+ 的突破

5.1 外推的挑战

当代 LLM 面临一个实际需求：在 4096 token 上训练，却需要在推理时处理几万甚至十几万 token 的长文档。直接使用超出训练长度的序列，大多数位置编码方案的性能都会严重退化。

图 7：不同位置编码方案的长度外推能力对比（示意）。训练长度=2048 时， Learned PE 和 Sinusoidal PE 在超出训练范围后性能急剧下降，RoPE 退化较缓，ALiBi 最为稳健。

5.2 RoPE 的外推问题

RoPE 的外推问题源于高频维度：当位置超出训练范围时， 高频维度的旋转角度进入了训练时从未见过的区域，导致注意力计算"失真"。 可以类比为：时钟的秒针转到了一个训练时从未出现过的角度。

5.3 解决方案：位置插值与频率修改

1

位置插值（PI）

将位置索引线性缩放到训练范围内：pos' = pos × Ltrain / Ltarget。 简单有效，但需要少量微调。代表：Meta 的 Code Llama。

2

NTK-Aware 缩放

修改 RoPE 的基频 base：base' = base × scaled/(d-2)。 只改变低频维度（时针），保留高频维度（秒针）的分辨率。无需微调。

3

YaRN

结合 NTK 缩放和注意力温度调整，按维度分组使用不同的缩放策略。 效果最好，但更复杂。代表：Mistral、LLaMA 3 的长上下文版本。

4

动态 NTK

在推理时根据实际序列长度动态调整 base 值。序列短时不缩放，序列超出训练长度时自动启用。 灵活但实现更复杂。

实际效果：通过 YaRN 等技术，基于 4K 上下文训练的 LLaMA 模型 可以在 128K 甚至更长的上下文中保持良好性能，且只需极少量的微调数据 （通常几百步即可适应新长度）。

七、总结

位置编码的演化反映了对两个核心问题的持续探索：

  1. 如何优雅地注入位置信息？ 从加法（Sinusoidal/Learned）到旋转（RoPE）到偏置（ALiBi）， 注入方式逐渐从"修改嵌入"演变为"修改注意力计算"，对模型的侵入性越来越小。
  2. 如何处理超长序列？ 从完全不能外推（Learned）到有限外推（Sinusoidal）到可扩展外推（RoPE + YaRN） 到天然外推（ALiBi），长上下文能力不断提升。
实践建议：
  • 构建 LLM：首选 RoPE，配合 YaRN 实现长上下文
  • 需要强外推能力且不想微调：考虑 ALiBi
  • 短序列分类/理解任务：Learned PE 仍然实用（如 BERT）
  • 教学/理解原理：从 Sinusoidal PE 入手最容易建立直觉

RoPE 之所以成为主流，是因为它在数学优美性、实现简洁性、性能表现和可扩展性之间 取得了最佳平衡。它用一个简单的旋转操作，以零参数的代价，实现了高质量的相对位置编码—— 这正是工程与数学完美结合的典范。
