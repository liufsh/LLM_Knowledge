引言：什么是大语言模型？

大语言模型（Large Language Model, LLM）本质上是一个概率预测器： 给定一段文本，它预测下一个最可能出现的词（token）。这个简单的目标， 配合海量数据和庞大的模型参数，催生了 GPT、LLaMA、Gemma 等令人惊叹的模型。

核心公式：给定前面的 token 序列 x1, x2, ..., xt-1， 模型计算下一个 token 的概率分布 P(xt | x1, ..., xt-1)， 然后从中采样或选取概率最高的 token。

本文将深入介绍当前主流 LLM（以 LLaMA 为代表的 Decoder-Only Transformer）的核心内容：

  1. 模型架构：从整体到组件，逐层拆解 Transformer 的内部结构
  2. 计算原理：Attention 机制的数学本质和直觉理解
  3. 端到端计算流程：从文本输入到输出的完整过程——Tokenization、Embedding、前向计算、输出解码
  4. 自回归生成：逐 token 生成的详细过程与采样策略
  5. 训练过程：损失函数、反向传播与参数更新
  6. KV Cache：推理加速的关键技术，理解其原理、收益和代价

一、模型整体架构

现代 LLM 几乎都采用 Decoder-Only Transformer 架构。与原始 Transformer 的 Encoder-Decoder 结构不同，Decoder-Only 去掉了 Encoder 和交叉注意力层，仅保留 带因果掩码的自注意力机制，更适合自回归文本生成任务。

2

对每个 token 独立做非线性变换。LLaMA 使用 SwiGLU 激活函数，维度为 2/3 × 4d。 这里存储了模型的大部分"知识"。

3

RMSNorm 预归一化

在每个子层之前（而非之后）进行归一化，提升训练稳定性。RMSNorm 比 LayerNorm 更高效， 省去了均值的计算。

4

残差连接

每个子层的输出与输入相加。这保证了梯度可以"绕过"子层直接回传， 是训练超深网络（80+ 层）的关键。

二、注意力机制：计算原理

2.1 核心思想

注意力机制的本质是一个加权信息检索过程。对于序列中的每个 token， 我们要回答一个问题："在理解当前词时，应该重点关注前文的哪些部分？"

类比：想象你在图书馆查资料。你心里有一个查询（Query）， 书架上每本书的目录是键（Key），书的内容是值（Value）。 你用查询去匹配每本书的目录（计算相似度），然后根据匹配程度加权提取内容。

2.2 Q、K、V 的生成

对于输入序列中的每个 token 向量 x（维度 dmodel），通过三组独立的线性变换 生成 Query、Key 和 Value：

Q = x · WQ ,    K = x · WK ,    V = x · WV

其中 WQ, WK, WV 是可学习的权重矩阵。直觉理解：

  • Query（查询）："我需要什么信息？"—— 当前 token 的需求表示
  • Key（键）："我能提供什么？"—— 每个 token 的索引/标签
  • Value（值）："我的实际内容是什么？"—— 每个 token 的信息内容

2.3 缩放点积注意力

Attention(Q, K, V) = Softmax(Q · KT / √dk) · V
图 2：缩放点积注意力的计算流程。输入 Q、K、V 经过矩阵乘法、缩放、可选掩码、Softmax 和加权求和五个步骤。

计算分为四步：

  1. 相似度计算：Q · KT 得到注意力分数矩阵， 形状为 [序列长度 × 序列长度]。每个元素表示两个 token 之间的"相关程度"。
  2. 缩放：除以 √dk（dk 是每个头的维度）。 这防止当 dk 较大时点积值过大，导致 Softmax 输出趋向 one-hot（梯度消失）。
  3. Softmax 归一化：将分数转化为概率分布，所有权重之和为 1。 在 LLM 中，先应用因果掩码（将未来位置设为 -∞），确保 token 只能关注过去。
  4. 加权求和：用注意力权重对 V 进行加权求和，得到当前 token 的输出表示。
为什么要缩放？假设 Q 和 K 的每个元素都是均值 0、方差 1 的随机变量， 它们的点积的方差为 dk。当 dk=128 时，点积的标准差为 √128 ≈ 11.3， 这样的大值会让 Softmax 的输出极度集中，梯度几乎为零。除以 √dk 可以将方差拉回 1。

2.4 因果掩码（Causal Mask）

LLM 是自回归模型：生成第 t 个 token 时只能看到前 t-1 个 token，不能"偷看"未来。 因果掩码通过将注意力矩阵的上三角（未来位置）设为 -∞ 来实现，Softmax 后这些位置的权重变为 0。

图 3：双向注意力（左，BERT 风格）vs 因果注意力（右，GPT/LLaMA 风格）。 右图中标"X"的位置被掩码屏蔽，token 只能关注自己及之前的位置。

三、多头注意力（Multi-Head Attention）

3.1 为什么需要多个头？

单个注意力头只能捕捉一种类型的关系。而在自然语言中，token 之间存在多种层次的依赖：

  • 语法关系：主语-谓语-宾语的结构性关联
  • 语义关系：同义词、上下位关系
  • 位置关系：相邻词之间的局部依赖
  • 长距离依赖：指代消解、跨段落的上下文关联

多头注意力让模型同时运行多个独立的注意力头，每个头可以自由学习不同类型的注意力模式。

MultiHead(Q, K, V) = Concat(head1, head2, ..., headh) · WO

其中 headi = Attention(Q · WiQ, K · WiK, V · WiV)
图 4：多头注意力机制。输入分别经过 h 组独立的线性变换和注意力计算， 结果拼接后通过一个线性层融合。

3.2 维度拆分

假设 dmodel = 4096，注意力头数 h = 32，则每个头的维度 dk = 4096 / 32 = 128。 总计算量与单头注意力完全相同——多头注意力不是增加计算，而是将同样的计算 拆分到多个并行的子空间中，从而捕捉更丰富的模式。

四、前馈网络（FFN）与知识存储

4.1 标准 FFN

在每个 Transformer Block 中，注意力层负责"决定关注什么"，而 FFN 负责"做实际的计算和知识提取"。 标准 FFN 是一个两层的全连接网络：

FFN(x) = ReLU(x · W1 + b1) · W2 + b2

中间层的维度通常是 dmodel 的 4 倍（如 dmodel=4096 时，中间维度为 16384）， 先"展开"到高维空间，经过非线性激活，再"压缩"回原维度。

4.2 LLaMA 的 SwiGLU FFN

LLaMA 将标准 FFN 替换为 SwiGLU FFN，使用门控机制和 SiLU 激活：

五、位置编码：RoPE

5.1 为什么需要位置编码？

注意力机制本身是置换不变的——打乱 token 的顺序，注意力计算的结果完全相同。 但语言是有序的（"猫吃鱼"和"鱼吃猫"意义完全不同），因此必须显式注入位置信息。

5.2 旋转位置编码（RoPE）

LLaMA 使用 RoPE（Rotary Position Embedding），其核心思想是： 通过旋转矩阵将位置信息编码进 Q 和 K 向量中，使得注意力分数自然地包含相对位置信息。

RoPE(x, pos) = x · R(pos)   其中 R(pos) 是基于位置 pos 的旋转矩阵

RoPE 的巧妙之处在于：

  • 相对位置编码：两个 token 的注意力分数只取决于它们的相对距离， 而非绝对位置。
  • 远程衰减：距离越远的 token 对之间的注意力自然衰减， 符合语言学中的"局部性"假设。
  • 外推能力：相比固定的正弦位置编码或可学习的位置嵌入， RoPE 在推理时可以更好地泛化到训练时未见过的长度。
直觉理解：想象二维平面上的向量。RoPE 将每个 token 的 Q/K 向量 按照其位置旋转不同的角度。当计算 Q · KT 时，结果只取决于两者的 角度差（即相对位置），而非各自的绝对角度。

6.1 第一步：Tokenization（分词）

模型不直接处理文字——它只接受整数 ID。Tokenizer 负责将文本切割为 token（子词单元），每个 token 对应词表中的一个 ID。

示例："The cat sat on" → Tokenizer → [The, ▁cat, ▁sat, ▁on] → ID: [450, 6635, 3290, 373]

LLaMA 使用 SentencePiece BPE（Byte Pair Encoding）分词器，词表大小为 32,000。 BPE 的核心思想是：

  • 高频词保持完整：如 "the"、"is" 是单个 token
  • 低频词被拆分为子词：如 "unhappiness" → ["un", "happiness"] 或 ["un", "happ", "iness"]
  • 未知字符回退到字节级别：保证任何 UTF-8 文本都能被编码
  • 数字被拆分为单个数字：如 "2024" → ["2", "0", "2", "4"]
Token ≠ 词：一个英文单词可能是 1-3 个 token，一个中文字通常是 1-2 个 token。 例如 "人工智能" 可能被切分为 ["人工", "智能"] 或 ["人", "工", "智", "能"]。 这直接影响模型能处理的实际文本长度——4096 token 的上下文窗口， 英文约 3000 词，中文约 2000-3000 字。

6.2 第二步：Token Embedding（词嵌入查表）

将每个 token ID 转换为一个 dmodel 维的连续向量。这通过一个 查表操作（而非矩阵乘法）实现：

Embedding Table: E ∈ RV × d   (V=词表大小, d=dmodel)

xi = E[token_idi]   →   取出第 token_id 行，得到一个 d 维向量

以 LLaMA-7B 为例：

  • 词表大小 V = 32,000，嵌入维度 d = 4,096
  • Embedding 表参数量 = 32,000 × 4,096 = 1.31 亿参数
  • 输入 4 个 token → 查表得到 4 个向量 → 形状 [4, 4096]
直觉理解：Embedding 表是在训练中学到的"词典"——每个 token 被映射到一个 高维空间中的点。语义相近的 token（如 "cat" 和 "dog"）在这个空间中距离较近。

6.3 第三步：Transformer 前向传播

Embedding 向量序列（形状 [seq_len, dmodel]）依次通过 N 层 Transformer Block。 每层进行的计算：

  1. RMSNorm：归一化输入，稳定数值范围
  2. Multi-Head Attention：生成 Q、K、V → 应用 RoPE → 计算注意力 → 输出
  3. 残差连接：attention_output + input
  4. RMSNorm：再次归一化
  5. SwiGLU FFN：非线性特征变换
  6. 残差连接：ffn_output + attention_output

经过 N 层后，输出的形状仍为 [seq_len, dmodel]——每个位置对应一个 融合了全部上下文信息的隐藏状态向量。

图 6：单个 token 在一层 Transformer 中的完整前向传播过程。 新 token 的 Q 与 KV Cache 中所有历史 K、V 进行注意力计算，然后经过 SwiGLU FFN。

6.4 第四步：输出层（LM Head）—— 从向量到词

Transformer 的输出是隐藏状态向量，我们需要将其转换为词表上的概率分布。 这分为三步：

Step A：最终 RMSNorm

对最后一层的输出做归一化。

Step B：线性映射到词表（Language Model Head）

logits = hlast · WvocabT   其中 hlast ∈ Rd, Wvocab ∈ RV × d

输出 logits ∈ RV（V=32,000 个原始分数）

这里的 Wvocab 通常与 Embedding 表共享权重（Weight Tying）， 即用同一个矩阵——输入时用它将 token ID 映射为向量，输出时用它的转置将向量映射回 token 空间。 这既减少了参数量，也让输入输出空间保持一致。

Step C：Softmax 归一化

P(tokeni) = exp(logiti) / ∑j exp(logitj)

将 32,000 个 logit 值转化为概率分布。每个值表示对应 token 成为下一个词的概率。

数值示例：假设 logits 中 "the" 对应的值为 3.2，"a" 为 1.8，"mat" 为 2.5，... 经过 Softmax 后，"the" 的概率可能是 0.35，"a" 是 0.09，"mat" 是 0.17，... 所有 32,000 个概率之和 = 1.0。

七、自回归生成的详细过程

7.1 Token-by-Token 生成

LLM 的文本生成是一个逐 token 的迭代过程。每一步只生成一个 token， 然后将其作为下一步的输入。整个过程就像一个"滚雪球"：

图 7：自回归生成的完整示例。每一步中，模型接收所有已有的 token， 经过前向计算得到概率分布，采样出下一个 token。绿色=缓存复用，黄色=新输入，红色=生成输出。

关键观察：

  • 每一步的输出依赖于之前所有 token（包括原始 prompt 和已生成的 token）
  • 生成是串行的——第 t 个 token 必须等第 t-1 个生成完成后才能开始
  • 这就是"自回归"（autoregressive）的含义：模型的输出会"回归"成自己的输入

7.2 Prefill 与 Decode 两阶段

实际推理分为两个截然不同的阶段：

图 8：Prefill 阶段（左）并行处理所有 prompt token，构建完整的 [n×n] 注意力矩阵和 KV Cache； Decode 阶段（右）每步只处理一个新 token，计算 [1×n] 的注意力向量。

Prefill 阶段

  • 处理整个 prompt（可能数百/数千 token）
  • 所有 token 并行通过 Transformer
  • 构建初始 KV Cache
  • 计算密集型：瓶颈是 GPU 算力（FLOPS）
  • 通常很快（数十毫秒到数秒）

Decode 阶段

  • 逐个生成新 token
  • 每步只处理 1 个 token
  • 复用并追加 KV Cache
  • 内存密集型：瓶颈是显存带宽（GB/s）
  • 较慢（每个 token 需要加载全部模型权重）
为什么 Decode 慢？每生成一个 token，GPU 都需要从显存中加载整个模型的权重 （LLaMA-7B 约 14 GB），但只做了极少量的计算（一个 token 的矩阵向量乘法）。 GPU 算力严重"吃不饱"，大部分时间花在等待数据从显存搬运到计算单元。 这就是所谓的 Memory-Bound（内存瓶颈）。

7.4 采样策略：如何从概率中选词

模型输出 32,000 个概率值后，如何选择下一个 token？不同的策略会产生风格迥异的文本：

图 9：四种采样策略对比。(a) 贪心解码总选最高概率；(b) 温度控制分布的"锐度"； (c) Top-k 只保留前 k 个候选；(d) Top-p 按累积概率截断。
1

Greedy Decoding（贪心）

总是选概率最高的 token。确定性输出，但容易重复且缺乏创造性。 适合翻译、摘要等需要精确的任务。

2

Temperature（温度）

logits 除以温度 T 后再 Softmax。T<1 使分布更尖锐（更确定）， T>1 使分布更平坦（更随机）。T=0 等价于贪心。

3

Top-k Sampling

只保留概率最高的 k 个 token，其余设为 0 后重新归一化再采样。 k 越小越保守，k 越大越多样。

4

Top-p / Nucleus Sampling

按概率从高到低排列，保留累积概率 ≥ p 的最小集合。 自适应调整候选数量——高置信时少选，低置信时多选。

实际应用中通常组合使用：例如 Temperature=0.7 + Top-p=0.9 + Top-k=50， 兼顾创造性和质量。对话类应用常用 T=0.7-1.0；代码生成常用 T=0-0.2（更确定性）。

7.5 停止条件

自回归生成在以下任一条件满足时停止：

  • EOS Token：模型生成了特殊的结束标记 </s> 或 <eos>
  • 最大长度：达到预设的最大生成 token 数
  • 停止词：遇到用户指定的停止字符串（如 "\n\n"）

八、训练过程：如何教会模型预测下一个词

8.1 训练目标：Next Token Prediction

LLM 的训练目标极其简洁：给定前面的 token，最大化正确下一个 token 的概率。 数学上，对于一个长度为 T 的训练序列，损失函数为：

L = - (1/T) ∑t=1T log P(xt | x1, ..., xt-1)

这就是交叉熵损失（Cross-Entropy Loss）。直觉理解： 模型在每个位置都给出 32,000 个 token 的概率预测，损失函数衡量的是 模型把正确答案排多高——如果把正确 token 预测为 100% 概率，损失为 0； 预测为很低概率，损失很大。

8.2 训练时的并行优势

训练 vs 推理的关键区别：训练时，模型可以一次性并行处理 整个训练序列（如 2048 或 4096 个 token）。因为训练数据中所有正确答案都已知 （Teacher Forcing），无需逐 token 生成。因果掩码确保每个位置只看到前面的 token， 使得单次前向传播就能同时计算所有位置的预测和损失。

这意味着一个 2048 token 的训练样本，一次前向传播就产生 2048 个预测， 每个位置都提供一个学习信号。这比推理时的逐 token 生成高效得多。

九、KV Cache：推理加速的核心技术

7.1 核心思想

KV Cache 的核心思想非常直观：缓存已计算过的 Key 和 Value，避免重复计算。

在自回归生成中，当计算第 t 个 token 的注意力时：

  • Query：只需要当前 token（第 t 个）的 Q 向量（1 × dk）
  • Key 和 Value：需要前面所有 token（1 到 t）的 K 和 V 向量

关键观察：前 t-1 个 token 的 K 和 V 在上一步已经计算过了！ 因此，只需要计算新 token 的 K、V，然后拼接到缓存中即可。

KV Cache 一句话总结： 在每个生成步骤中，不重新计算所有 token 的 K 和 V， 而是只计算新 token 的 K 和 V，并追加到缓存中。 注意力计算变为：新 Q × 全部缓存 KT → 权重 → 权重 × 全部缓存 V。

十、KV Cache 优化技术

由于 KV Cache 的内存瓶颈，研究者提出了多种优化方案：

1

Multi-Query Attention (MQA)

所有注意力头共享同一组 K 和 V，只有 Q 各自独立。 KV Cache 减少为原来的 1/h（h 为头数）。代表：PaLM、Falcon。

2

Grouped-Query Attention (GQA)

将头分为若干组，同组内共享 K、V。在 MQA 和 MHA 之间取平衡。 代表：LLaMA 2、Mistral。

3

量化 KV Cache

将 KV Cache 从 FP16 量化到 INT8 或 INT4，直接减少 2-4 倍内存。 需要权衡精度损失。

4

PagedAttention (vLLM)

借鉴操作系统的虚拟内存管理，将 KV Cache 分页存储， 避免预分配造成的内存碎片和浪费。代表：vLLM。

十一、完整推理流程总结

综合以上内容，LLM 的推理分为两个阶段：

阶段一：Prefill（预填充）

处理输入 prompt 的所有 token。这一步是并行的——所有 token 同时经过 Transformer 计算， 生成初始的 KV Cache。这一步通常是计算密集型（受限于 GPU 算力）。

阶段二：Decode（解码生成）

逐 token 生成新内容。每步只处理一个新 token，利用 KV Cache 避免重复计算。 这一步通常是内存密集型（受限于显存带宽——需要频繁读取 KV Cache 和模型权重）。

性能关键点： Prefill 阶段的速度主要取决于 GPU 的算力（FLOPS）； Decode 阶段的速度主要取决于显存带宽（GB/s）， 因为每生成一个 token 都需要从显存中加载全部模型权重和 KV Cache。 这就是为什么 Decode 阶段往往是推理的瓶颈。

十二、总结

本文系统介绍了大语言模型的完整知识体系：

  1. 模型架构：Decoder-Only Transformer 由 Token Embedding、N 层 Transformer Block （每层含因果自注意力 + SwiGLU FFN + RMSNorm + 残差连接）和输出头组成。
  2. 计算原理：注意力机制通过 Q-K 相似度计算 + Softmax 归一化 + V 加权求和 实现动态的信息检索。多头注意力在多个子空间并行捕捉不同关系，RoPE 编码相对位置。
  3. 端到端流程：文本经过 Tokenization → Embedding 查表 → N 层 Transformer 前向传播 → LM Head 线性映射 → Softmax 归一化，完成从字符串到概率分布的完整计算。
  4. 自回归生成：Prefill 阶段并行处理 prompt，Decode 阶段逐 token 生成， 配合 Temperature / Top-k / Top-p 采样策略控制输出的多样性。
  5. 训练过程：以 Next Token Prediction 为目标，通过交叉熵损失 + 反向传播 + AdamW 优化器更新参数，训练时可并行处理整个序列。
  6. KV Cache：通过缓存历史 token 的 K、V 向量避免重复计算， 将解码阶段的注意力计算从 O(n2) 降为 O(n)，是推理加速的基石。
一句话理解 LLM：一台由数十层 Transformer Block 构成的"预测引擎"—— 将文本分词为 token，嵌入为向量，经过注意力和 FFN 反复提炼， 最终映射回词表得到概率分布，逐词生成文本。 训练时并行预测整个序列，推理时借助 KV Cache 高效逐词输出。
