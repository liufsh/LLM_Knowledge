引言：为什么需要 Multi-Token Prediction？

自 GPT 以来，几乎所有主流大语言模型的训练目标都是Next-Token Prediction（NTP） ——给定前文，预测下一个 token。这个看似简单的目标成就了 ChatGPT 等产品，但它也有深层的局限性： 每次只看"一步之遥"，模型缺乏对未来多步； 推理时逐 token 自回归生成，速度被显存带宽（Memory-Bound）严重限制。

MTP（Multi-Token Prediction）通过让模型同时预测未来 k 个 token， 从两个维度带来收益：
(1) 训练质量提升——多步预测提供更丰富的梯度信号，迫使模型学习更深层的语义规划；
(2) 推理速度加速——一次前向传播产生多个候选 token，配合验证机制实现 2-3 倍加速。
图 1：NTP vs MTP。NTP 每步只预测 1 个 token；MTP 每步同时预测未来 k 个 token，提供更丰富的训练信号和推理并行性。

一、背景知识：Next-Token Prediction 及其局限

1.1 NTP 回顾

标准自回归语言模型的训练目标是最大化给定前文下一个 token 的对数似然：

LNTP = − (1/T) Σt=1..T log Pθ(xt | x1, ..., xt−1)

推理时，模型逐步采样：每一步需要完整的前向传播（所有 Transformer 层）， 只产出一个 token。这个过程是严格串行的。

1.2 NTP 的三大局限

1

训练信号短视

每个位置只监督"下一个 token"，模型不需要规划未来就能获得低 loss—— 它可以靠局部 n-gram 模式得到不错的 NTP 分数，但缺乏深层语义理解。

2

推理速度瓶颈

自回归逐 token 生成时，每步都要加载全部模型权重但只产出一个 token， 计算量/访存比（Arithmetic Intensity）极低——是典型的 Memory-Bound 问题。

3

规划能力弱

人类写作时会"先想好后面几个词再落笔"，NTP 模型没有这种前瞻性。 这在代码生成、数学推理等需要长程规划的任务中尤为突出。

4

Teacher Forcing 偏差

训练时总是看到 ground truth 前文（Teacher Forcing）， 但推理时看到的是自己生成的（可能有误的）token——这种暴露偏差导致错误累积。

1.3 推理的 Memory-Bound 问题

图 2：NTP 需要 6 步串行前向传播生成 6 个 token；MTP（k=3）理想情况下仅需 2 步。

二、MTP 核心原理

2.1 基本思想

MTP 的核心非常简单：在每个位置 t，不只预测 xt+1，而是同时预测 xt+1, xt+2, ..., xt+k。 其训练损失为 k 个位置的 NTP 损失之和：

LMTP = Σj=1..k λj · Lj

Lj = − (1/T) Σt=1..T log Pθ,j(xt+j | x1, ..., xt)

其中：

  • k：预测步数（prediction depth），通常 k = 2~8
  • λj：第 j 步的损失权重，通常 λ1 = 1（NTP 主损失），λj>1 ∈ [0.1, 1.0]
  • Pθ,j：第 j 个预测头的输出概率分布

2.2 为什么多步预测能提升模型质量？

信息论视角：预测第 t+k 个 token 需要对位置 t 的隐藏状态编码更长远的语义信息。 NTP 只需要编码"下一个词是什么"的信息，但预测 t+3 要求模型在位置 t 就"想好"后面 3 步的走向—— 这迫使 Transformer 的中间表示学习更抽象、更具规划性的特征。
图 3：MTP 的多步预测迫使隐藏状态 h_t 编码更远未来的语义信息，提升表示质量。

2.3 MTP 的两大应用场景

A

训练阶段：辅助损失

MTP 作为额外的训练目标，辅助主 NTP 损失。训练完成后可以丢弃额外的预测头， 模型架构不变但质量更好。代表：Meta MTP、DeepSeek-V3。

B

推理阶段：推测解码

多个预测头在推理时并行生成候选 token，主模型通过一次前向传播验证/接受，实现加速。 代表：Medusa、EAGLE、DeepSeek-V3 推理。

三、MTP 架构分类学

不同的 MTP 方法在"如何预测第 2, 3, ..., k 个 token"的架构设计上有显著差异。核心的设计选择包括： 预测头是独立并行还是顺序级联？是否共享 Backbone？预测头的结构是轻量 Linear 还是完整 Transformer？

四、Meta MTP：系统论证多步预测的训练价值

Meta 在 2024 年发表了 "Better & Faster Large Language Models via Multi-Token Prediction"， 第一次大规模、系统性地论证了 MTP 在训练中的价值。

4.1 架构设计

Meta 采用独立并行头（模式 A）：在共享 Backbone 之上挂载 k 个独立的输出头， 每个头预测不同位置的下一个 token。

图 5：Meta MTP 架构。共享 Backbone 产出隐藏表示 h_t，k 个独立的 LM Head 分别预测 x_{t+1}, x_{t+2}, ..., x_{t+k}。

4.2 关键实验结论

1

模型越大收益越大

在 7B 参数以下 MTP 收益有限；13B+ 模型中 MTP 显著提升下游任务表现——这可能因为大模型有足够容量编码多步信息。

2

代码任务收益最大

代码生成（HumanEval, MBPP）上 MTP-4 比 NTP 提升 12%+。代码的结构性和长程依赖使多步预测信号特别有价值。

3

k=4 是最优平衡点

k=2~4 收益递增，k>4 后边际收益递减甚至轻微下降。k=4 在训练效率和质量间达到最优。

4

训练 FLOPs 开销适中

额外 Head 只是线性层，增加约 ~15% 训练 FLOPs（k=4），但无推理额外开销（Head 可丢弃）。

4.3 Meta MTP 的内存优化：顺序预测+因果掩码

k 个独立 Head 都需要对完整词表做 softmax，显存开销为 k × (T × |V|)。 Meta 提出逐头顺序计算损失（而非同时 materialize 所有 logits）来减少峰值显存：

显存峰值 = max(T × |V|) 而非 k × T × |V|

五、DeepSeek-V3 MTP：级联式多步预测

DeepSeek-V3（2024.12）将 MTP 作为核心训练目标之一（与 MoE、MLA 并列）， 并在架构上做了独特的创新——顺序级联预测（模式 B）。

5.1 架构详解

图 6：DeepSeek-V3 MTP 架构。Backbone 输出 h⁰，MTP Module 1 接收 [h⁰, Emb(x_{t+1})] 产出 h¹ 并预测 x_{t+2}； MTP Module 2 接收 [h¹, Emb(x_{t+2})] 产出 h² 并预测 x_{t+3}。所有模块共享 LM Head。

5.2 训练目标

Ltotal = LNTP + λ · Σj=1..k LMTP,j

DeepSeek-V3 使用 k = 1（即只额外预测 1 步），λ = 0.3
注意：虽然 DeepSeek-V3 的论文标题写的是"MTP"，但实际上它只预测额外 1 个 token（k=1）， 相当于2-Token Prediction。这是为了在训练开销和收益之间取得平衡—— 多 1 步的预测信号已经足以显著提升模型质量。

DeepSeek-V3 的 MTP 模块在推理时有双重价值：训练好的 MTP Head 可以直接作为推测解码的 Draft 模型， 无需额外训练一个独立的小模型：

六、推理加速方案：Medusa 与 EAGLE

Medusa 和 EAGLE 是 MTP 在纯推理加速方向的代表方案。 它们给已训练好的 LLM 添加额外的预测头，通过推测解码实现无损加速。

6.1 Medusa

图 8：Medusa 在冻结 LLM 之上添加多个轻量 Head 并行预测后续 token。每个 Head 独立——命中率逐步递减。

Medusa-2 进一步引入 Tree Attention——每个 Head 不只生成 top-1 候选， 而是生成 top-k 候选，构成一棵"候选树"，一次验证整棵树，大幅提升接受率。

6.2 EAGLE（Extrapolation Algorithm for Greater Language-model Efficiency）

图 9：EAGLE 在特征空间（而非 token 空间）进行自回归草稿生成。特征比 token 分布更平滑、更可预测，因此命中率更高。

七、推测解码的 Token 验证与接受原理

推测解码（Speculative Decoding）能实现无损加速的核心保证在于： 它通过一个精心设计的拒绝采样（Rejection Sampling）算法， 确保最终输出的 token 序列严格服从大模型（Target Model）的原始分布—— 数学上完全等价于逐 token 自回归解码，没有任何质量损失。 本节将深入推导这一机制的数学原理。

7.1 问题设定

记：

  • p(x | prefix)：大模型（Target Model）在给定前缀下的 token 分布
  • q(x | prefix)：小模型 / Draft Head 在给定前缀下的 token 分布
  • 目标：从 q 中采样 k 个草稿 token，再用一次 p 的前向传播并行验证它们， 最终输出的 token 必须精确服从 p 的分布
核心约束：无论 Draft 模型 q 的质量如何，最终输出必须在统计上等价于从 p 逐步采样。 q 越接近 p 则接受率越高、加速越明显，但即使 q 完全随机，输出也保证正确（只是退化为无加速）。

7.2 单步验证：修正拒绝采样

假设 Draft 模型已经采样了一个 token x̂ ~ q(·|prefix)。我们需要决定是否接受它， 并保证接受后的分布 = p(·|prefix)。算法如下：

图 11-A：单步 Token 验证算法。接受概率 α = min(1, p(x̂)/q(x̂))：Draft 给的概率比 Target 低时 α=1（必接受）；比 Target 高时按比例拒绝。

7.3 数学证明：为什么输出分布等于 p

我们需要证明：对任意 token x，最终输出 x 的概率 = p(x)。

P(输出 = x) = P(Draft 采样到 x 且接受) + P(Draft 被拒绝后修正采样到 x)

第一项：Draft 采样到 x 且接受

P(x̂ = x, 接受) = q(x) · min(1, p(x)/q(x)) = min(q(x), p(x))

第二项：Draft 被拒绝后从修正分布采样到 x

总拒绝概率为：

P(拒绝) = Σx' q(x') · (1 − min(1, p(x')/q(x'))) = Σx' max(0, q(x') − p(x'))

修正分布为：

p修正(x) = max(0, p(x) − q(x)) / Σx' max(0, p(x') − q(x'))

因此第二项为：

P(拒绝) · p修正(x) = max(0, p(x) − q(x))

两项相加：

P(输出 = x) = min(q(x), p(x)) + max(0, p(x) − q(x)) = p(x)   ✓
完美等价！这个等式对任意 q 和 p 都成立——无论 Draft 模型多差， 输出始终精确服从 Target 模型 p 的分布。q 的质量只影响接受率（速度），不影响正确性。

假设词表大小 |V|=5，某步的 Target 和 Draft 分布如下：

7.5 多步验证：逐位贪心验证

实际推测解码中 Draft 一次生成 k 个 token。验证是从前往后逐位进行的： 一旦某一位被拒绝，该位及其后续所有位都被丢弃。

图 11-C：k=4 多步验证。前 2 个 token 被接受，第 3 个被拒绝（Draft 把 "in" 的概率高估了 3 倍），第 4 个自动丢弃。最终本轮产出 3 个有效 token。

7.6 接受率与加速比的关系

设单步接受率为 α（Draft 与 Target 的吻合度），期望每轮接受的 token 数为：

E[接受数] = Σi=1..k αi = α(1 − αk) / (1 − α)

加上拒绝后修正采样的 1 个 token，每轮总产出 = E[接受数] + 1
图 11-D：接受率 α 与每轮期望产出关系（k=5）。α=0.8 时每轮约 3.9 个 token，接近 4 倍加速。α=0.9+ 时接近理论上限 k+1=6。

7.7 Tree-based 验证（Medusa-2 / EAGLE-2）

线性验证的问题是：一旦某位拒绝，后续全部丢弃——即使后面的草稿可能正确。 Tree-based 验证通过构建候选树解决这一问题：每位保留多个候选（top-k），形成一棵树， 一次验证覆盖多条路径。

图 11-E：线性验证只看 1 条路径，遇到 "in" 就截断；Tree 验证同时探索多条分支，发现 "on" 路径可以走更远——最终多接受 1 个 token。

Tree-based 验证通过 Tree Attention（特殊的因果掩码）在一次前向传播中同时验证所有候选路径：

Tree Attention Mask:   M[i][j] = 1 当且仅当节点 j 是节点 i 在树中的祖先
Tree 验证的代价：候选树有 N 个节点，则验证需要处理 N 个 token 的前向传播（而非 k 个）。 关键是 N 不能太大——通常控制在 60~120 个节点。EAGLE-2 引入了动态树结构： 根据 Draft Head 的置信度自适应调整树的宽度和深度，在接受率和验证开销之间取得最优平衡。

十、实践选型指南

10.1 根据场景选择 MTP 方案

A

从零预训练

选 Meta MTP 或 DeepSeek-V3 级联。如果模型 ≥13B 且训练语料充足， MTP 辅助损失可显著提升代码和推理能力。推荐 k=2~4，λ=0.3~1.0。

B

已有模型加速推理

选 EAGLE > Medusa > Speculative Decoding。EAGLE 在大多数场景命中率最高（~85-90%）， Medusa 实现最简单。无需重新训练主模型。

C

训练+推理一体化

选 DeepSeek-V3 级联 MTP。训练时作为辅助损失提升质量，推理时 MTP Head 直接作为 Draft，一箭双雕。

D

零额外训练成本

选 Lookahead Decoding。利用 Jacobi 迭代在不修改模型的前提下实现并行解码，加速约 1.5-2 倍。

10.2 常见问题与陷阱

实践注意事项：
  • MTP 不等于更好的 NTP：额外 Head 的预测质量通常低于主 Head——第 k 步预测的准确率可能只有第 1 步的 60-70%。MTP 的价值在于梯度信号对 Backbone 的改善，而非额外 Head 自身的精度。
  • 小模型收益有限：Meta 发现 7B 以下模型 MTP 收益不显著——小模型的容量不足以同时编码多步信息。
  • 推测解码有接受率上限：Draft 质量不够时，接受率低反而比普通解码更慢（验证开销 > 节省的步数）。
  • Batch 推理时加速比降低：推测解码在 batch_size=1 时加速最明显；大 batch 时主模型已 Compute-Bound，加速比下降。
  • KV Cache 管理：推测解码需要管理"临时"KV Cache（草稿 token 的缓存），被拒绝后需回滚——这增加工程复杂度。

十一、总结与展望

Multi-Token Prediction 正在从"实验性技术"走向"预训练标配"。DeepSeek-V3 的实践证明， 即使只额外预测 1 个 token（k=1），也能在保持训练效率的同时显著提升模型质量和推理速度。

MTP 的未来方向：
  • 更大的 k 值探索：当前 k=2~4 是主流，未来可能结合更长的预测步数和更好的课程学习策略
  • 与 MoE 的深度集成：DeepSeek-V3 已将 MTP + MoE 结合，未来可能出现"专家级 MTP Head"
  • Process-level MTP：不只预测 token，而是预测推理步骤（与 PRM 结合）
  • 自适应 k：根据生成内容的不确定性动态调整预测步数——简单续写多预测几步，复杂推理少预测
  • 与 RLHF 对齐的交互：MTP 训练出的 Draft Head 在 RLHF 阶段如何协同优化仍是开放问题
