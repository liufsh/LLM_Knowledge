引言：为什么大模型需要"思考"

标准 LLM 采用System 1 式的直觉快速响应——看到问题后立即生成答案。 这在简单任务上表现出色，但面对数学证明、逻辑推理、复杂编程等需要多步推理的任务时， 直接输出答案往往出错。Chain-of-Thought（CoT，思维链）让模型在给出最终答案前， 先生成一系列中间推理步骤——正如人类"打草稿"一样，将复杂问题逐步分解求解。

图 1：标准回答 vs CoT 推理。CoT 在回答前先生成中间推理步骤，使复杂任务的准确率大幅提升。
CoT 的核心洞察（Scaling Test-Time Compute）： 传统 Scaling Laws 关注训练阶段的计算量（更大模型 + 更多数据）。CoT 开辟了另一个维度—— 在推理阶段投入更多计算量（生成更长的思考过程），同样可以大幅提升模型能力。 这被称为 Test-Time Compute Scaling。

1.2 CoT 的工作机制

CoT 的核心原理并不复杂：让模型在输出最终答案之前，先生成一段中间推理过程。 从信息论的角度，这等价于增加模型的计算深度—— 每个推理 token 都是一次"计算步骤"，将不可一步完成的复杂推理分解为多个可完成的子步骤。

图 2：CoT 的计算原理。标准 LLM 的计算深度固定为 L 层，CoT 通过生成 n 个思考 token 将有效计算深度扩展到 L×n。

二、CoT 模型训练与微调

2.1 训练范式总览

让 LLM 获得强大 CoT 推理能力，主要有三种训练范式： CoT SFT（监督微调）、CoT RL（强化学习）和CoT 蒸馏。 以 DeepSeek-R1 的技术报告为核心参考，这三种方法各有适用场景。

图 3：CoT 推理能力的三大训练范式。CoT RL 是最强但最贵的方案，CoT 蒸馏是性价比最高的方案，CoT SFT 适合快速实验。

2.2 CoT RL 训练详解（核心方法）

CoT RL 是当前最先进推理模型（o1、R1）的核心训练方法。 其关键思路是：在可以自动验证答案的任务上（数学、代码）， 用任务的正确性作为奖励信号，通过强化学习训练模型自主探索推理策略。

图 4：DeepSeek-R1 的 CoT RL 训练流程。冷启动 → 大规模 GRPO RL → 拒绝采样 SFT → 二轮对齐 RL，四阶段逐步提升推理能力。

2.3 CoT 训练中的涌现现象

DeepSeek-R1-Zero 的惊人发现——CoT 从 RL 中自发涌现：
  • 自我验证（Self-Verification）：模型学会在推理过程中回头检查自己的步骤
  • 反思（Reflection）：模型生成 "Wait, let me reconsider..."、"Hmm, that doesn't seem right" 等自我纠错模式
  • 探索多路径：模型学会 "Let me try a different approach" 主动切换推理策略
  • 推理长度自适应：简单问题生成短思考链，复杂问题自动生成长链推理
  • "Aha moment"：训练过程中模型突然学会在关键步骤重新审视推理，准确率阶跃提升
这些能力都不是人工设计或标注的——它们完全从 RL 的奖励信号中自发涌现。

三、CoT 训练数据设计与准备

3.1 各训练阶段的数据需求

图 5：CoT 各阶段训练数据全景。冷启动靠少量精标数据，RL 靠大量可验证题库，蒸馏靠强模型的推理输出，对齐靠偏好和安全数据。

3.2 RL 训练题库的设计要点

1

可验证性是前提

RL 的奖励信号来自答案验证。数学题可核验最终数值，代码题可运行测试用例，逻辑题可检查真值。开放式问答不适合纯 RL 训练。

2

难度梯度覆盖

题库需包含从简单到竞赛级的完整难度梯度。过易 → 模型不需要深度推理即可答对；过难 → 奖励信号过于稀疏，训练效率低。

3

领域多样性

单一领域训练的推理能力泛化性差。需覆盖代数、几何、组合、概率、数论、编程（多语言）、逻辑推理等。

4

数据去污染

必须严格排除评测集中的题目（AIME、MATH、HumanEval 等），防止 data contamination 导致虚假的高分。

四、CoT 推理的关键技术

4.1 思考 Token 的格式设计

推理模型需要区分"思考过程"和"最终回答"。主流做法是使用特殊标记包裹思考内容：

典型的推理输出格式： 
<think>
让我分析这个问题。需要求 1 到 100 中所有 3 的倍数之和。
首先，3 的倍数有：3, 6, 9, ..., 99
这是一个等差数列，首项 a₁=3，末项 aₙ=99，公差 d=3
项数 n = (99-3)/3 + 1 = 33
求和 S = n(a₁+aₙ)/2 = 33×(3+99)/2 = 33×51 = 1683
让我验证一下：33×51 = 33×50 + 33 = 1650 + 33 = 1683 ✓
</think>

1 到 100 中所有 3 的倍数之和为 **1683**。

4.2 关键推理技巧

1

自我验证

"让我检查一下这个结果..."——模型在推理过程中回头验证中间步骤，减少累积错误。这是 RL 训练中自发涌现的能力。

2

回溯与重试

"这条路走不通，换个方法..."——模型主动放弃错误的推理路径，尝试新的解法。类似 Tree of Thoughts 的内化版本。

3

问题分解

"这个问题可以分为三个子问题..."——将复杂问题分解为可独立解决的子问题，逐个攻克后合并答案。

4

类比推理

"这类似于之前遇到的 XX 问题..."——利用训练中学到的模式迁移到新问题，减少从零推理的难度。

4.3 Test-Time Compute Scaling

推理模型的一个核心特性是思考时间越长，性能越好——直到边际收益递减。 这构成了一个新的 Scaling 维度：不是增大模型参数，而是增加推理时的计算量。

Performance ∝ log(Test-Time Compute)

思考 token 数从 1K → 10K → 100K，性能持续提升但边际递减

5.1 全景对比

图 6：主流推理模型技术路线对比。DeepSeek-R1 是唯一完全开源的推理模型，其蒸馏系列在同参数量下表现最优。

5.2 DeepSeek-R1 技术深度剖析

DeepSeek-R1 的四阶段训练流水线：
  1. 冷启动 SFT：用数千条带 <think> 标记的长 CoT 数据微调 DeepSeek-V3 Base，教会模型输出结构化推理格式
  2. 推理 RL（面向推理）：在数学和代码任务上进行大规模 GRPO 训练。奖励信号 = 答案正确性 + 格式规范性。训练过程中模型推理链逐步变长（从 ~1K 到 ~10K+ tokens）
  3. 拒绝采样 + SFT：用 RL 模型对新问题集生成大量推理轨迹，筛选正确的做 SFT。同时混入通用对话和写作数据（~20 万条），保持通用能力
  4. 二轮 RL（全场景对齐）：在推理任务上继续用规则奖励，在通用任务上使用人类偏好奖励。同时施加安全和格式约束

5.3 OpenAI o1/o3 系列

OpenAI 的推理模型系列（o1 → o1-pro → o3 → o4-mini）是商业推理模型的标杆。 虽然训练细节高度保密，但从公开信息可以推断：

  • 训练方法：大规模 RL + 过程奖励模型（PRM），推测使用了比 R1 更大规模的 RL 训练
  • 过程奖励模型：不仅奖励最终答案正确，还对推理过程的每一步进行评分（Process Reward Model）
  • 推理 token 隐藏：出于安全和商业考虑，o1 的思考过程不对用户展示原文，只显示摘要
  • 工具调用 + 推理：o3 开始支持在推理过程中调用工具（搜索、代码执行），将 CoT 与 Agent 结合
  • 自适应计算：o3 支持 low/medium/high 三种思考级别，让用户在速度和质量间权衡

适合用 CoT 的场景

  • 数学证明与计算
  • 复杂编程与算法设计
  • 逻辑推理与分析

不适合用 CoT 的场景

  • 创意写作

  • 延迟敏感的实时应用
  • 成本敏感的批量处理

6.4 Thinking Budget：推理成本控制

推理模型的成本远高于普通模型。Thinking Budget（思考预算）是控制成本的核心机制—— 限制模型生成的最大思考 token 数量。

Thinking Budget适用场景延迟成本效果
关闭思考简单问答、翻译~1s1×与普通模型相同
Low（~1K tokens）中等难度推理~5s3~5×显著提升
Medium（~10K tokens）复杂数学/代码~30s10~20×大幅提升
High（~100K tokens）竞赛级难题~5min50~100×接近模型上限

七、CoT 的局限与挑战

7.1 已知问题

问题表现原因缓解措施
过度推理 简单问题也生成冗长思考链 RL 训练激励更长推理，模型难以判断何时"够了" Thinking Budget；路由模型；长短 CoT 联合训练（Kimi k1.5）
推理幻觉 推理过程看似合理但前提错误 模型"编造"不存在的定理或性质用于推理 自我验证训练；工具辅助验证（计算器/代码执行）
语言混杂 思考过程中中英文混杂 训练数据中英文推理数据更多 语言一致性奖励；更多非英语 CoT 数据
推理循环 在错误路径上反复尝试，不收敛 缺乏有效的"放弃"策略 最大步数限制；反思机制；回溯训练
安全隐患 思考过程中可能出现不安全内容 思考空间比直接回答更难约束 安全 RL 对齐；思考内容过滤；隐藏原始思考

7.2 "思考是否真实"的争论

Faithfulness 问题：模型的思考过程是否真正反映了其内部计算？
  • 研究表明，CoT 的思考过程与模型的实际推理路径可能不完全一致——模型可能在思考中"事后合理化"而非真正"推理"
  • 隐藏思考过程（如 o1）使外部审查更加困难，引发 AI 安全领域的关注
  • 目前没有可靠方法完全验证 CoT 的"忠实性"（faithfulness）

八、发展趋势与未来

1

推理 + Agent 融合

o3/Claude Opus 4 已开始将 CoT 与工具调用结合——模型在推理过程中可以调用搜索、代码执行等工具辅助思考，形成"思考中行动"的新范式。

2

多模态推理

推理能力从纯文本扩展到图像（几何题看图推理）、视频（理解动态场景）、音频等多模态输入，形成统一的多模态推理模型。

3

高效推理

减少推理冗余：CoT 压缩（只保留关键步骤）、隐式推理（在隐层中完成推理而非生成显式 token）、推测解码加速。

4

自适应计算深度

模型自动判断问题难度，动态调整思考长度——简单题秒答，难题深思熟虑。消除"用牛刀杀鸡"的计算浪费。

图 8：CoT 技术演进路线。从最初的 Prompt 工程到 RL 训练的原生能力，再到与 Agent 融合和高效推理，CoT 正在成为 LLM 的标配能力。

总结

Chain-of-Thought 推理代表了大模型从"快速直觉"到"深度思考"的范式跃迁。本文系统介绍了 CoT 的完整体系：

  1. 推理原理：CoT 通过生成中间推理步骤将有效计算深度从 L 扩展到 L×n，本质是 Test-Time Compute Scaling
  2. 训练方法：CoT RL（GRPO）是核心方法——用可验证任务的正确性作为奖励，让推理能力从 RL 中自发涌现
  3. 训练数据：冷启动靠少量精标数据，RL 靠大量可验证题库，蒸馏靠强模型的推理输出——高质量蒸馏数据的效率远超预期
  4. 关键技术：自我验证、回溯重试、问题分解等推理技巧从 RL 训练中自然涌现
  5. 主流方案：OpenAI o1/o3 是商业标杆，DeepSeek-R1 是开源标杆，蒸馏系列是性价比之选
  6. 部署应用：智能路由 + Thinking Budget 是成本控制的关键；推理模型适用于复杂推理任务，不适合简单问答
CoT 的深层意义：CoT 揭示了一个深刻的发现—— 推理能力可以从简单的奖励信号（答对/答错）中自发涌现， 无需人工设计推理模板或标注推理过程。这意味着通向更强通用智能的路径可能比预想的更简单： 给模型足够的计算量和正确的奖励信号，让它自己学会思考。
