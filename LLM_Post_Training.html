引言：为什么需要后训练对齐？

经过大规模预训练的语言模型具有强大的语言理解和生成能力，但它们本质上只是在预测下一个 token—— 这意味着它们会如实"反映"训练数据中的一切，包括偏见、有害内容和不符合人类期望的回答方式。 一个只做了预训练的模型（Base Model），你问它"如何做蛋炒饭？"，它可能会续写出一篇论文引言， 而不是给出有条理的步骤。

后训练对齐的三大目标（3H 原则）：
(1) Helpful（有用）——能理解用户意图，给出高质量回答；
(2) Harmless（无害）——拒绝有害请求，不产出危险内容；
(3) Honest（诚实）——承认不知道，不编造事实。

后训练（Post-Training）是预训练之后的所有训练阶段的总称，包括监督微调（SFT）和 人类偏好对齐两个核心阶段。本文重点讨论偏好对齐技术。

一、RLHF 总览：三阶段对齐框架

RLHF（Reinforcement Learning from Human Feedback，从人类反馈中强化学习）是 OpenAI 在 InstructGPT 中提出的经典对齐范式。 其核心思想是：先用人类的偏好判断训练一个奖励模型（Reward Model），再用这个奖励模型作为信号，通过强化学习优化语言模型。

图 2：RLHF 三阶段流程全景。阶段 1 训练 SFT 模型；阶段 2 用人类偏好训练奖励模型；阶段 3 用 PPO 算法和奖励信号优化策略模型。
1

SFT 阶段

用高质量 (指令, 回答) 对微调 Base Model，使其学会"对话格式"。这一步让模型从"续写文本"变成"回答问题"。

2

RM 阶段

收集人类对多个回答的偏好排序（A 比 B 好），训练一个奖励模型来给回答打分——这是将人类偏好"数字化"的关键。

3

RL 阶段

用 PPO 算法，以奖励模型的评分为信号，迭代优化语言模型。同时用 KL 散度约束防止模型偏离太远。

4

迭代对齐

实际部署后，继续收集用户反馈，迭代更新 RM 和策略模型。ChatGPT 就是这样持续进化的。

二、强化学习背景知识

在深入各对齐算法之前，我们需要掌握 RL 的核心概念。RLHF / PPO / GRPO 本质上都是将语言模型视为一个策略（Policy）， 用 RL 方法优化它。理解以下概念是后续所有算法的基础。

2.1 将 LLM 生成建模为 MDP

LLM 即策略：在 RLHF 框架中，语言模型 πθ 被视为一个策略： 给定当前"状态"（prompt + 已生成的 token 序列），输出一个"动作"（下一个 token）的概率分布。
图 2：将 LLM 生成建模为马尔科夫决策过程（MDP）。状态是已生成的序列，动作是下一个 token，奖励在序列结束时由 RM 给出。

2.2 策略梯度（Policy Gradient）

策略梯度是所有 RL 对齐算法的理论基础。其核心定理（REINFORCE）为：

∇θ J(θ) = Ey~πθ(·|x) [ ∇θ log πθ(y|x) · A(x, y) ]

其中：

  • log πθ(y|x)：策略对数似然，对于自回归 LLM：log πθ(y|x) = Σt=1..T log πθ(yt|x, y<t)
  • A(x, y)：优势函数（Advantage），衡量回答 y 比"平均水平"好多少
直觉理解：如果 A > 0（好回答），则增大 log πθ(y|x)，即让模型更可能生成 y； 如果 A < 0（差回答），则减小，即让模型更不可能生成 y。梯度方向 = 对数似然方向 × 优势函数。

2.3 优势函数（Advantage Function）

优势函数的估计方式是各算法的核心区别：

A(s, a) = Q(s, a) − V(s)
方法优势估计方式是否需要 Critic
PPO (GAE)At = Σl=0..∞ (γλ)l · δt+l，其中 δt = rt + γV(st+1) − V(st)✓ 需要 Critic V(s)
GRPOÂi = (ri − μgroup) / σgroup（组内 z-score）✗ 不需要
REINFORCEAi = R(x, yi) − b，b 为基线（如均值）✗ 不需要
RLOOAi = R(x, yi) − (1/(G−1)) Σj≠i R(x, yj)✗ 不需要

2.4 KL 散度（KL Divergence）

KL 散度衡量两个概率分布之间的"距离"，在对齐训练中用于约束策略不偏离参考模型太远：

KL(πθ ‖ πref) = Ey~πθ [ log (πθ(y|x) / πref(y|x)) ]

对于自回归 LLM，Token 级别的 KL 散度为：

KLtoken = Σt=1..T Σv∈V πθ(v|st) · log (πθ(v|st) / πref(v|st))
实践中的近似：由于对完整词表求和代价太高，GRPO / PPO 实际使用采样近似：
KL ≈ Σt [ log πθ(yt|st) − log πref(yt|st) ]
即只计算实际采样到的 token 上的对数概率差。这是一个无偏估计。

2.5 Policy 熵（Policy Entropy）

策略熵衡量策略输出的不确定性/多样性，是 RL 训练中至关重要的监控指标：

H(πθ(·|s)) = −Σv∈V πθ(v|s) · log πθ(v|s)

对于整个序列的平均 Token 熵：

H̄ = (1/T) Σt=1..T H(πθ(·|st)) = −(1/T) Σt=1..T Σv∈V πθ(v|st) · log πθ(v|st)

数值计算示例

假设词表大小 |V|=4，在某个时间步 t，策略输出：

图 3：Policy 熵计算对比。均匀分布的熵为 ln(|V|) = 1.386（最大），尖锐分布的熵仅 0.428。 熵过低意味着模型输出"过于确定"，可能导致多样性丧失。

2.6 熵正则化（Entropy Bonus）

许多 RL 算法在目标函数中加入熵奖励（entropy bonus），鼓励策略保持一定的探索性：

J(θ) = E [ R(x, y) − β · KL(πθ ‖ πref) + α · H(πθ) ]

其中 α 是熵系数。三者的关系：

  • R(x,y)：鼓励高质量回答 → 拉高好 token 的概率
  • KL 惩罚：防止偏离 πref 太远 → "刹车"
  • 熵奖励：防止策略"坍缩"到少数几个 token → 保持多样性
熵在 GRPO 中的关键作用：GRPO 的 DeepSeek-R1 训练中，熵的监控至关重要。 如果训练过程中 entropy 持续下降趋近于零，模型会丧失探索能力， 反复生成相同的"模板回答"——这就是熵坍缩（Entropy Collapse）。

三、奖励模型（Reward Model）

奖励模型是 RLHF 的"桥梁"——它将主观的人类偏好转化为可微分的标量信号， 使得梯度优化成为可能。RM 通常由一个与策略模型结构相似的 Transformer 组成，去掉最后的 token 预测头， 替换为一个输出标量分数的线性层。

2.1 数据收集

给定同一个 Prompt，让模型（或不同模型）生成多个回答，由人类标注员进行成对比较：

图 3：奖励模型训练数据的收集过程。每个 Prompt 生成多个候选回答，人类标注员进行排序，产生成对偏好数据。

2.2 Bradley-Terry 模型与训练目标

RM 的训练基于 Bradley-Terry 模型：假设人类选择回答 yw（winner）优于 yl（loser） 的概率可以用两者奖励差值的 sigmoid 函数表示：

P(yw ≻ yl | x) = σ(R(x, yw) − R(x, yl))

训练目标是最大化人类标注正确的对数似然：

LRM = −E(x, yw, yl) [ log σ(R(x, yw) − R(x, yl)) ]
直觉理解：这个损失函数在做什么？它让奖励模型学会：给人类偏好的回答打更高的分。 当 R(x, yw) 远大于 R(x, yl) 时，σ 接近 1，log 接近 0，loss 很小——这正是我们想要的。

2.3 RM 的挑战

奖励黑客（Reward Hacking）：RM 不是完美的人类偏好代理。策略模型会找到 RM 的"漏洞"—— 例如生成冗长但实际空洞的回答，因为 RM 可能错误地认为"更长 = 更好"。 这是 RLHF 中最棘手的问题之一。

四、PPO（Proximal Policy Optimization）

PPO 是 OpenAI 于 2017 年提出的策略梯度算法，因其训练稳定性好、超参数相对不敏感， 成为 RLHF 中最常用的 RL 算法。InstructGPT、ChatGPT、Claude 早期版本均使用 PPO 进行对齐训练。

3.1 核心思想

PPO 的目标是最大化奖励的同时约束策略更新幅度。直觉上：每一步更新不要走太远， 因为走太远可能掉进"悬崖"——这就是"近端"（Proximal）的含义。

3.2 RLHF 中的 PPO 目标函数

J(θ) = Ex~D, y~πθ [ R(x, y) − β · KL(πθ(y|x) ‖ πref(y|x)) ]

其中：

  • R(x, y)：奖励模型给出的分数
  • β · KL(...)：KL 散度惩罚项，防止策略 πθ 偏离参考模型 πref（通常是 SFT 模型）太远
  • β：KL 惩罚系数，控制"探索"与"保守"的平衡

3.3 PPO-Clip 机制

PPO 通过裁剪（Clip）概率比来限制每步更新的幅度：

rt(θ) = πθ(at|st) / πθold(at|st)

LCLIP = E [ min( rt(θ) · At,   clip(rt(θ), 1−ε, 1+ε) · At ) ]

其中 At 是优势函数（通过 GAE 估计），ε 通常取 0.2。

图 4：PPO-Clip 的核心机制。当 A>0（好动作），概率比超过 1+ε 时被裁剪，防止过度增加； 当 A<0（坏动作），概率比低于 1-ε 时被裁剪，防止过度惩罚。这确保了训练的稳定性。

3.4 RLHF-PPO 的完整训练流程

图 5：RLHF-PPO 的训练流程。需要同时维护 4 个模型，显存需求是 PPO 最大的工程挑战。

3.5 PPO 的优缺点

✓ 优势

  • 经过 ChatGPT 等产品的大规模验证
  • 可以在线生成数据并即时优化
  • 理论上可以达到最优策略
  • 支持复杂的奖励信号组合

✗ 劣势

  • 需要 4 个模型，显存需求巨大
  • 训练不稳定，超参数敏感
  • 奖励模型存在 Reward Hacking 风险
  • 实现复杂，工程难度高

五、DPO（Direct Preference Optimization）

DPO（Rafailov et al., 2023）是后训练对齐领域的一次范式革新。 它的核心洞察是：RLHF 中的 RM + RL 可以被化简为一个简单的分类损失函数， 完全跳过奖励模型训练和强化学习优化的复杂过程。

4.1 核心推导思路

DPO 的推导从 RLHF 的 KL 约束优化问题出发。标准 RLHF 要解决：

maxπ Ex~D, y~π [ R(x,y) ] − β · KL(π ‖ πref)

这个优化问题有一个闭式解：

π*(y|x) = (1/Z(x)) · πref(y|x) · exp(R(x,y) / β)

反解出奖励函数：

R(x,y) = β · log( π*(y|x) / πref(y|x) ) + β · log Z(x)

关键一步：将这个等式代入 Bradley-Terry 模型后，配分函数 Z(x) 恰好被消掉！ 最终得到 DPO 损失函数：

LDPO(θ) = −E(x, yw, yl) [ log σ( β · (log πθ(yw|x) / πref(yw|x) − log πθ(yl|x) / πref(yl|x)) ) ]
DPO 的优雅之处：它用"策略模型与参考模型的对数概率比的差" 隐式地定义了奖励——不需要单独训练奖励模型，也不需要强化学习。整个训练像做普通的监督学习一样简单。

4.2 DPO vs RLHF 架构对比

图 6：RLHF (PPO) vs DPO 架构对比。RLHF 需要 4 个模型和复杂的在线采样 + RL 训练循环；DPO 仅需 2 个模型，用类似交叉熵的损失直接优化。

4.3 DPO 的直觉理解

图 7：DPO 做的事情非常直观——让好回答的概率升高，差回答的概率降低，且重点关注模型"犯错"最严重的样本。

4.4 DPO 的优缺点

✓ 优势

  • 实现极其简单——几十行代码
  • 仅需 2 个模型，显存需求减半
  • 训练稳定，无 RL 的不稳定性
  • 不存在 Reward Hacking 问题
  • 训练速度快，可用标准 SFT 流程

✗ 劣势

  • 依赖离线数据，无法在线探索
  • 偏好数据质量直接决定效果上限
  • 分布偏移：训练数据的策略 ≠ 当前策略
  • β 超参数较敏感
  • 在极大规模上可能不如在线 RLHF

六、GRPO 深度详解（Group Relative Policy Optimization）

GRPO 由 DeepSeek 团队（Shao et al., 2024）提出，是 DeepSeek-Math 和 DeepSeek-R1 的核心对齐算法。 它针对 PPO 的两大痛点做了关键改进：去掉 Critic 模型和用组内相对排名替代绝对奖励。 本节将深入其数学推导、数值计算过程以及 Token 级别的 KL 惩罚细节。

6.1 动机：PPO 的痛点

1

Critic 代价高昂

PPO 需要一个 Critic（价值模型）Vφ 来估计 GAE 优势。对于 7B 模型，这意味着额外 ~14GB 显存 + 训练开销。

2

Critic 估计不准

LLM 场景下 Critic 需要在超长序列上做值估计，训练困难，估计偏差大。不准确的 V(s) 导致 GAE 优势质量差。

3

绝对奖励不稳定

RM 的绝对分数存在 scale 偏差——不同 Prompt 难度不同，0.7 分在简单题可能很差，在难题可能很好。

4

样本效率低

PPO 每个 Prompt 只采样一个回答，单次 rollout 的方差极大。需要大量样本才能获得可靠的梯度估计。

6.2 核心思想：组采样 + 相对优势

GRPO 的两步创新：
(1) 对每个 Prompt 采样一组（G 个）回答，获得同一 Prompt 下的多个奖励；
(2) 在组内做 z-score 标准化作为优势——好坏是相对于同组其他回答而言的，天然消除了 Prompt 难度差异。

6.3 算法完整流程

图 10：GRPO 完整算法流程与数值示例。G=8 采样中 4 个正确（r=1）、4 个错误（r=0），z-score 标准化后优势分别为 +1.0 和 −1.0。

6.4 数学公式详解

（a）组内 z-score 优势估计

μ = (1/G) Σi=1..G ri      σ = √( (1/G) Σi=1..G (ri − μ)2 )

Âi = (ri − μ) / σ

（b）Token 级 PPO-Clip 目标

与标准 PPO 不同，GRPO 将序列级优势 Âi 广播到每个 token：

LGRPO(θ) = −(1/G) Σi=1..G (1/|yi|) Σt=1..|yi| [ min(ρi,t · Âi,   clip(ρi,t, 1−ε, 1+ε) · Âi) ]

其中 ρi,t = πθ(yi,t | x, yi,<t) / πθold(yi,t | x, yi,<t)

（c）Token 级 KL 散度惩罚

GRPO 使用非对称的 Token 级 KL 惩罚（与参考模型计算）：

DKLtoken = (1/|yi|) Σt=1..|yi| [ πref(yi,t|st) / πθ(yi,t|st) − log(πref(yi,t|st) / πθ(yi,t|st)) − 1 ]
注意：上式是 Schulman 近似 KL（k3 估计），而非标准 KL。这一近似在实际中更稳定—— 它保证非负性，且在 πθ 和 πref 差距不大时近似等于标准 KL。 DeepSeek-R1 的开源代码中正是使用了此形式。

（d）GRPO 完整目标

JGRPO = LGRPO(θ) − β · DKLtoken

6.7 奖励形式：RM vs 规则验证器

奖励来源公式适用场景代表
RM（神经网络） ri = Rφ(x, yi) ∈ R 通用对话、创意写作等 InstructGPT, ChatGPT
结果验证器 (ORM) ri = 𝟙(answer(yi) == ground_truth) 数学、代码等可验证任务 DeepSeek-R1
过程验证器 (PRM) ri = Σstep R(stepj) · γj 长链推理、需要中间奖励 OpenAI PRM, Math-Shepherd
混合奖励 ri = λ·RRM + (1−λ)·Rrule 兼顾质量与正确性 DeepSeek-V3
GRPO 在推理任务中的巨大成功：DeepSeek-R1 使用 GRPO + 二值规则奖励（答案正确 r=1，错误 r=0）， 在 AIME 2024 数学竞赛和 Codeforces 编程中取得了媲美 OpenAI o1 的表现。这证明了不需要人类标注的 RM， 仅用可验证的规则信号就能训练出强大的推理能力。

6.8 GRPO 优缺点

✓ 优势

  • 去掉 Critic，节省 ~25% 显存
  • 组内相对优势天然消除 Prompt 难度差异
  • 多采样降低梯度估计方差
  • 配合规则奖励可完全去除人类标注
  • DeepSeek-R1 实战验证

✗ 劣势

  • G 倍采样增加推理开销（G=8~64）
  • 序列级优势广播到 token 不够精细
  • 仍需 Reference Model 计算 KL
  • 组大小 G 的选择需要权衡
  • 全组奖励相同时优势为 0（无梯度信号）

七、GSPO（Group Sampling Policy Optimization）

GSPO 是在 GRPO 基础上提出的改进方法，核心思路是：在组采样的框架下引入更精细的采样策略和优势分配机制， 解决 GRPO 中序列级优势广播粒度不够以及采样效率的问题。

7.1 GRPO 的局限与 GSPO 的动机

GRPO 的核心局限：GRPO 将整个序列的奖励 ri z-score 标准化后得到优势 Âi， 然后将同一个 Âi 广播到序列的每一个 token。 这意味着：一个整体好的回答中，每一个 token 都被同等鼓励——包括其中可能不好的中间步骤； 反之，整体差的回答中，好的部分也被同等惩罚。
图 13：GRPO 将同一个序列级优势广播到所有 token（坏 token 也被鼓励）；GSPO 为每个 token 分配差异化优势。

7.2 GSPO 的核心机制

GSPO 保留了 GRPO"组采样 + 无 Critic"的优点，在此基础上引入了三个关键改进：

1

Token 级优势重分配

将序列级优势 Âi 根据每个 token 位置的信息增益（πθ 与 πref 的偏离度）进行加权重分配。 偏离越大的 token 被分配越多的优势权重。

2

自适应采样策略

根据 Prompt 的当前 pass rate（通过率）动态调整组大小 G。通过率极高/极低的 Prompt 增大 G 以获得更细粒度的信号。

3

熵感知 KL 惩罚

将策略熵纳入 KL 惩罚的权重调节中——当策略熵过低（趋向坍缩）时增大 KL 惩罚力度，防止过早收敛。

4

组间对比学习

对同一批次中的不同 Prompt 组之间也引入对比信号，使模型不仅学习"同题好坏"，还学习"跨题偏好一致性"。

7.3 GSPO 的目标函数

GSPO 的损失函数在 GRPO 基础上增加了 Token 级优势权重和熵正则项：

LGSPO(θ) = −(1/G) Σi=1..G (1/|yi|) Σt=1..|yi| [ wi,t · min(ρi,t · Âi, clip(ρi,t, 1−ε, 1+ε) · Âi) ]

− β · DKLtoken(πθ ‖ πref) + α · H̄(πθ)

其中权重 wi,t 的计算：

wi,t = softmaxt( |log πθ(yi,t|st) − log πref(yi,t|st)| / τ )

直觉：策略与参考模型分歧越大的 token 位置，获得越大的优势权重—— 这些位置是策略"做出了不同于 SFT 的决策"的地方，应该被更强地鼓励或惩罚。

八、Policy 熵正则化详解

Policy 熵（策略熵）在后训练中扮演着"探索的守护者"角色。 熵过低意味着策略退化为确定性策略，丧失多样性和探索能力（熵坍缩）； 熵过高则意味着策略太随机，无法利用已学到的知识。本节深入讨论熵的计算、监控和在各算法中的具体应用。

8.1 熵的数学定义与性质

H(πθ(·|s)) = −Σv∈V πθ(v|s) · log πθ(v|s)

关键性质：

  • 非负性：H ≥ 0，当且仅当策略为确定性（one-hot）时 H = 0
  • 上界：H ≤ log|V|，当且仅当策略为均匀分布时取等号。对 |V|=32000，Hmax ≈ 10.37 nats
  • 凹函数：H 关于概率分布是凹的，这意味着最大化熵有唯一最优解（均匀分布）

8.2 完整数值计算：从 Logits 到 熵

实际实现中，我们从模型的 logits 出发，经过 softmax 得到概率，再计算熵。以词表大小 |V|=5 为例：

图 15：从 LLM logits 到 policy 熵的完整计算流程。当前策略熵 0.925 nats，占最大熵的 57.5%，表示策略有一定确定性但仍保持探索。

8.3 熵坍缩（Entropy Collapse）

熵坍缩是 RL 训练中最危险的现象之一：策略的熵在训练过程中持续快速下降， 最终趋近于零——模型对几乎所有输入都输出几乎相同的、高度确定的回答。

图 16：训练过程中 Policy 熵的变化。健康训练中熵平稳下降后稳定在合理区间； 熵坍缩时熵快速降到接近零，模型退化；熵过高则策略太随机。

8.5 熵与 KL 散度的关系

熵和 KL 散度虽然概念不同，但在对齐训练中紧密相关：

KL(πθ ‖ πref) = H(πθ, πref) − H(πθ)

即：KL 散度 = 交叉熵 − 策略熵
关键洞察：当我们最小化 KL(πθ ‖ πref) 时，等价于同时在做两件事：
(1) 最小化交叉熵 H(πθ, πref)——让 πθ 与 πref 更接近；
(2) 最大化策略熵 H(πθ)——KL 最小化天然会保护策略的多样性！
这就是为什么 KL 惩罚即使没有显式的 entropy bonus，也能一定程度上防止熵坍缩。

8.6 实践建议：熵的监控与调控

1

必须监控的指标

训练中实时记录：平均 token 熵 H̄、KL 散度、奖励曲线。三者需联合观察：reward 上升 + entropy 稳定 = 健康训练。

2

熵下降过快的应对

增大 KL 系数 β 或增加 entropy bonus α；降低学习率；增大组采样大小 G（更多样本 → 更稳定梯度）。

3

熵不下降的应对

说明学习率太小或 KL 惩罚过强。策略未能有效利用奖励信号。适当减小 β，或增大 learning rate。

4

合理的熵范围

对于 32K 词表，初始 SFT 模型的 token 熵通常在 2~4 nats。训练后稳定在 1~3 nats 是合理的。低于 0.5 需要警惕。

九、其他前沿对齐方法

9.1 KTO（Kahneman-Tversky Optimization）

KTO（Ethayarajh et al., 2023）的创新在于不需要成对比较数据—— 只需要每个回答的二元标签（👍好 / 👎差），这比收集成对偏好数据容易得多。

LKTO = Ey~desirable[ 1 − σ(β · (rθ(x,y) − zref)) ] + Ey~undesirable[ 1 − σ(β · (zref − rθ(x,y))) ]

其中 rθ(x,y) = log(πθ(y|x) / πref(y|x)) 是隐式奖励， zref 是参考点。这一设计受到前景理论（Kahneman & Tversky）的启发： 人类对损失比对收益更敏感。

9.2 ORPO（Odds Ratio Preference Optimization）

ORPO（Hong et al., 2024）的目标更加激进——将 SFT 和对齐合并为一步训练。 它在标准的 NLL loss 上增加一个基于 odds ratio 的偏好项：

LORPO = LNLL(yw) − λ · log σ( log (oddsθ(yw) / oddsθ(yl)) )

其中 oddsθ(y) = Pθ(y|x) / (1 − Pθ(y|x))。 ORPO 不需要参考模型，进一步减少了显存需求。

9.3 REINFORCE 变体（REINFORCE Leave-One-Out）

在 DeepSeek-R1 和一些最新工作中，经典的 REINFORCE 算法也被重新启用。 REINFORCE Leave-One-Out (RLOO) 通过留一法减小方差：

Âi = R(x, yi) − (1/(G−1)) ∑j≠i R(x, yj)

与 GRPO 思路类似，但使用 REINFORCE 梯度估计而非 PPO-Clip。 简单、有效，特别适合有明确奖励信号（如数学正确性）的场景。

9.4 IPO、SimPO 等 DPO 变体

1

IPO

Identity PO：修复 DPO 在偏好确定性极高时的过拟合问题，用平方损失替代 log-sigmoid。

2

SimPO

Simple PO：不需要参考模型，用序列平均对数概率作为隐式奖励，加入长度归一化。

3

RSO

Rejection Sampling Optimization：从最优策略中采样来纠正分布偏移，然后用 DPO loss。

4

Online DPO

在线 DPO：用当前策略在线生成回答并即时获取偏好标注，缓解离线 DPO 的分布偏移问题。

十一、实践选型指南

11.1 如何选择对齐算法？

A

资源有限 + 有偏好数据

选 DPO。只需 2 个模型，训练简单稳定。适合绝大多数团队的通用对齐需求。

B

只有好/差标签

选 KTO。不需要成对偏好数据，只需二元评价。数据收集成本最低。

C

数学/代码推理强化

选 GRPO。配合规则验证器（答案正确性检查），不需要人类标注，效果极佳。

D

追求极致效果 + 充足资源

选 PPO (RLHF)。在线采样 + RL 优化的上限最高，但需要强工程能力。

11.3 训练经验与常见陷阱

常见陷阱：
  • 数据质量 > 算法选择：高质量的偏好数据对最终效果的影响远大于 DPO vs PPO 的算法差异
  • SFT 是基础：跳过 SFT 直接做对齐通常效果很差。SFT 建立格式和基本能力，对齐做精细调优
  • KL 惩罚很重要：过小会导致模式崩塌（degenerate），过大会使模型几乎不更新
  • Reward Hacking：PPO 训练中 reward 持续上升但实际质量下降，说明 RM 被 hack 了
  • DPO 的长度偏好：DPO 容易学到"更长 = 更好"的偏置，需要在数据中控制长度分布

十二、总结与展望

后训练对齐是将"语言模型"变成"AI 助手"的关键步骤。从 2022 年 InstructGPT 的 RLHF 三阶段范式， 到 2023 年 DPO 的简化革新，再到 2024-2025 年 GRPO/REINFORCE 在推理强化中的复兴， 这一领域正在快速演进。

未来的核心方向：
  • 推理能力的 RL 强化：以 o1/R1 为代表，通过 RL 训练模型"思考"能力，这是 2025 年最热门的方向
  • 规则奖励替代人类标注：在可验证的领域（数学、代码）中，规则验证器比人类标注更准确、更便宜
  • 在线 + 离线混合：结合在线采样（PPO/GRPO 的探索能力）和离线数据（DPO 的训练效率）
  • Constitutional AI：用 AI 自身来评估回答质量，减少对人类标注的依赖
  • Process Reward Model：不只评估最终结果，还评估推理过程的每一步
