大模型评测指标与计算原理详解

从 Perplexity 到 pass@k —— 多模态大模型的全维度度量体系
文本生成 知识推理 代码生成 数学推理 多模态理解 安全对齐

引言：为什么需要系统的评测体系

大语言模型（LLM）的能力日益多元——文本理解与生成、代码编写、数学推理、图像理解、语音交互…… 单一指标早已无法全面衡量一个模型的实力。构建系统的评测体系，需要理解每个指标 度量什么能力、如何计算、以及有哪些局限。

评测的两大范式： (1) 自动指标（Automatic Metrics）——可复现、可大规模运行，如 Perplexity、BLEU、pass@k； (2) 人类评估 / 竞技场（Human Eval / Arena）——更接近真实用户感受，如 Chatbot Arena ELO 评分。 二者互补，缺一不可。
图 1：大模型评测的六大维度。每个维度有其专属的指标族和 Benchmark 数据集。

一、文本生成指标

1.1 困惑度 Perplexity（PPL）

困惑度是衡量语言模型"建模质量"最基础的指标。直觉上，PPL 越低，模型对文本的预测越精准—— 它对下一个 token 越"不困惑"。

PPL = exp( − (1/N) ∑i=1N log P(xi | x<i) )

其中 N 是 token 总数，P(xi | x<i) 是模型在给定前文条件下预测第 i 个 token 的概率。

图 2：Perplexity 的直觉。好模型对下一个 token 高度"自信"（概率集中），差模型则"困惑"于大量候选。

PPL 优势

  • 无需人工标注，纯自监督计算
  • 直接反映模型的语言建模能力
  • 可跨数据集横向对比
  • 训练过程中天然可监控

PPL 局限

  • 不直接衡量生成质量或有用性
  • 不同 tokenizer 的 PPL 不可直接比较
  • 对 repetition / hallucination 不敏感
  • PPL 低不代表回答正确或安全

1.2 BLEU（Bilingual Evaluation Understudy）

BLEU 最初为机器翻译设计（Papineni et al., 2002），通过度量模型输出与参考答案之间的 n-gram 精确率来评估文本质量。

BLEU = BP · exp( ∑n=1N wn log pn )

其中：

  • pn = 修正的 n-gram 精确率（Candidate 中与 Reference 匹配的 n-gram 占比）
  • wn = 权重（通常 uniform: wn = 1/N）
  • BP = 短文本惩罚因子 Brevity Penalty
BP = min(1,  exp(1 − r/c))

r = 参考译文长度,  c = 候选译文长度;  当 c < r 时 BP < 1（惩罚过短的输出）
图 3：BLEU 修正精确率示例。未修正时 "the the the the" 获得 100% unigram 精确率，修正（clipping）后降为 50%。

1.3 ROUGE（Recall-Oriented Understudy for Gisting Evaluation）

ROUGE（Lin, 2004）面向文本摘要任务，侧重召回率——参考文本中有多少内容被模型输出覆盖。

N

ROUGE-N

n-gram 召回率。Reference 中有多少 n-gram 出现在了 Candidate 中。ROUGE-1（unigram）和 ROUGE-2（bigram）最常用。

L

ROUGE-L

最长公共子序列（LCS）。不要求连续匹配，能捕捉更灵活的结构相似性。F1 值 = 精确率与召回率的调和平均。

ROUGE-Nrecall = |匹配的 n-gram 数| / |Reference 中的 n-gram 总数|

ROUGE-LF1 = (1+β2) · Plcs · Rlcs / (β2 · Plcs + Rlcs)

其中 Rlcs = LCS(Ref, Cand) / |Ref|,  Plcs = LCS(Ref, Cand) / |Cand|

1.4 BLEU vs ROUGE 核心区别

图 4：BLEU 关注"输出准不准"（精确率），ROUGE 关注"覆盖全不全"（召回率）。

1.5 BERTScore

BERTScore（Zhang et al., 2020）突破了传统 n-gram 匹配的局限，利用预训练语言模型的 上下文嵌入 计算 token 级别的语义相似度。

RBERT = (1/|Ref|) ∑x∈Ref maxy∈Cand cos(hx, hy)

PBERT = (1/|Cand|) ∑y∈Cand maxx∈Ref cos(hx, hy)

FBERT = 2 · PBERT · RBERT / (PBERT + RBERT)

其中 hx、hy 是 BERT 编码的上下文向量。 优势："happy" 和 "joyful" 能获得高匹配分，而 n-gram 方法会判为完全不匹配。

二、知识与推理评测

2.1 评测范式：选择题准确率

知识与推理领域的 Benchmark 多数采用多选题（Multiple Choice）格式， 模型从 A/B/C/D 中选择答案，指标为简单的准确率（Accuracy）。

Accuracy = 正确回答的题数 / 总题数 × 100%
评测实现细节很重要：选择题评测通常有两种实现方式—— (1) 概率法：比较模型对各选项 token 的 log-probability，选概率最高的； (2) 生成法：让模型直接生成答案字母。两种方式结果可能不同，对比时需统一。

2.3 MMLU 详解

MMLU（Massive Multitask Language Understanding, Hendrycks et al., 2021）是目前引用最广、 最具标杆意义的知识评测。覆盖人文、社科、STEM、专业四大领域 57 个子任务。

图 5：MMLU 涵盖 57 个科目，分为 STEM、人文、社科、专业四大领域，是衡量 LLM 知识广度的核心 Benchmark。

2.4 Few-shot 与 Chain-of-Thought

知识评测通常在 Prompt 中提供若干示例（Few-shot），引导模型理解任务格式。 0-shot 不提供示例；5-shot 提供 5 个示例。 报告分数时必须标注 shot 数。

Chain-of-Thought (CoT)： 在 Few-shot 示例中加入推理过程，显著提升数学和推理任务的准确率。 GSM8K 上 CoT 可使准确率从 ~20% 飙升到 ~80%+。报告时需标注是否使用 CoT。

三、代码生成评测

3.1 核心指标：pass@k

代码生成的评测思路：给模型一道编程题，让它生成代码，然后运行测试用例检验正确性。 pass@k 是最核心的指标——从 n 次生成中随机取 k 个，至少有一个通过所有测试的概率。

pass@k = 1 − C(n−c, k) / C(n, k)

n = 总生成次数（通常 n ≥ k），c = 通过测试的次数，C(·,·) = 组合数
图 6：pass@k 的完整计算流程。pass@1 衡量"一次就对"的能力；pass@k（k>1）衡量"多试几次能否做出"的能力。

四、数学推理评测

4.1 核心指标与评测方式

数学推理评测的核心指标是准确率（Accuracy）——模型给出的最终答案是否与标准答案完全一致。 评测时通常要求模型在推理链末尾将答案放在特定格式中（如 \boxed{}）， 由评测脚本自动提取并比对。

图 7：数学评测流程——模型生成完整推理链，评测脚本提取最终答案并与标准答案精确匹配。

4.2 Majority Voting（多数投票）与 Best-of-N

类似代码的 pass@k，数学评测也常采用多次采样策略来提升准确率：

N

Majority Voting (maj@k)

采样 k 次，取出现次数最多的答案作为最终答案。如 k=64 时，即使单次准确率仅 60%，多数投票后可达 90%+。

B

Best-of-N (bon@k)

使用奖励模型（RM）对 k 个生成结果打分，选分数最高的。上限比 majority voting 更高但依赖 RM 质量。

maj@k:   answer = argmaxa |{i : responsei 的答案 = a,  i = 1..k}|

5.3 VQA Accuracy 计算

VQAv2 使用了一种独特的"软准确率"来处理人类标注的分歧：

VQA Accuracy = min(1,  |同意该答案的标注人数| / 3)

每道题由 10 个标注者作答。对于模型给出的答案，如果有 ≥3 个标注者也给出了同样的答案， 则准确率为 1；否则按比例计算。这种设计优雅地处理了主观问题。

5.4 CIDEr（图像描述评测）

CIDEr（Consensus-based Image Description Evaluation）专为图像描述任务设计， 通过 TF-IDF 加权的 n-gram 匹配来衡量生成描述与参考描述的一致性。

CIDErn = (1/M) ∑j ( gn(c) · gn(rj) ) / ( ‖gn(c)‖ · ‖gn(rj)‖ )

gn 为 TF-IDF 加权的 n-gram 向量；c = candidate, rj = 第 j 个 reference
CIDEr 的设计思想：TF-IDF 加权使得"通用描述"（如 "a photo of"）权重很低， 而"区分性描述"（如 "a red bicycle"）权重很高——鼓励生成具有信息量的描述。

六、图像生成评测

6.1 FID（Fréchet Inception Distance）

FID 是衡量图像生成质量最广泛使用的指标。核心思想：用预训练的 Inception-v3 网络提取真实图像和 生成图像的特征分布，然后计算两个分布之间的 Fréchet 距离。FID 越低越好。

FID = ‖μr − μg‖2 + Tr(Σr + Σg − 2(ΣrΣg)1/2)

μr, Σr = 真实图像特征的均值和协方差；μg, Σg = 生成图像特征的均值和协方差
图 9：FID 计算流程。真实图像和生成图像分别通过 Inception-v3 提取特征，建模为高斯分布后计算 Fréchet 距离。

6.2 CLIP Score（图文对齐度）

CLIP Score 衡量生成图像与文本 prompt 之间的语义对齐程度——即图像是否"画对了题"。 利用 CLIP 模型分别编码图像和文本，计算余弦相似度。

CLIP Score = max(0,  cos(Eimg(image), Etxt(prompt))) × 100

6.3 其他图像生成指标

指标 度量维度 计算原理 ↑/↓
IS（Inception Score） 质量 + 多样性 KL 散度: P(y|x) 应清晰（质量），P(y) 应均匀（多样性） ↑
FID 质量 + 多样性 特征空间的 Fréchet 距离 ↓
CLIP Score 图文对齐 CLIP 嵌入的余弦相似度 ↑

七、语音模态评测

7.1 语音识别（ASR）

语音识别的核心指标是 WER（Word Error Rate），通过编辑距离衡量识别结果与真实文本的差异。

WER = (S + D + I) / N × 100%

S = 替换数, D = 删除数, I = 插入数, N = 参考文本词数
图 10：WER 计算示例。"quick" 被替换为 "duck"（S=1），"brown" 被删除（D=1），WER = 2/4 = 50%。

7.2 语音合成（TTS）指标

指标 度量维度 计算原理
MOS（Mean Opinion Score） 主观质量 人类评分 1~5 分的平均值，是语音质量的"金标准"
PESQ 客观语音质量 模拟人耳感知，比较参考与失真语音的差异
Speaker Similarity 说话人相似度 说话人验证模型（如 WavLM）提取声纹的余弦相似度
WER of ASR 可懂度 用 ASR 系统转写合成语音，WER 越低越清晰

八、安全、对齐与人类偏好

8.1 TruthfulQA（真实性）

TruthfulQA（Lin et al., 2022）评测模型是否会生成人类常犯的错误或迷信说法。 包含 817 个问题，覆盖健康、法律、金融、逻辑等容易产生误导的领域。

TruthfulQA 指标 = (Truthful & Informative 的回答占比) × 100%

由微调的 GPT-judge 模型自动判断回答是否 truthful 且 informative

8.2 Chatbot Arena ELO

LMSYS Chatbot Arena 是目前最权威的人类偏好评测平台。 用户向两个匿名模型提问，然后选出更好的回答，通过 ELO 评分系统 排名。

1

盲评机制

用户不知道正在对比哪两个模型，消除品牌偏见。

2

ELO 排名

借鉴国际象棋 ELO 评分系统：胜率高的模型分数上升，败者下降。公式考虑对手强度。

3

大规模投票

已积累数百万次人类投票，统计显著性远超传统人类评估。

4

实时更新

新模型可快速接入，排行榜持续更新，反映最新模型格局。

ELO 更新:  R'A = RA + K · (SA − EA)

EA = 1 / (1 + 10(RB−RA)/400)

R = 当前分数, S = 实际结果 (1/0.5/0), E = 预期胜率, K = 更新速率

8.3 LLM-as-Judge

用强大的 LLM（如 GPT-4）作为评委来评估其他模型的输出质量。这已成为开放式生成任务的主流评测方式。

优势

  • 比人类评估便宜 10~100 倍
  • 可大规模、可复现
  • 与人类评估相关性高（~80%+）
  • 支持细粒度评分维度

局限

  • 位置偏见（倾向选第一个）
  • 长度偏见（倾向更长回答）
  • 自我偏好（倾向同族模型）
  • 无法超越评委模型自身能力

9.2 如何读一份模型报告中的评测数据

阅读评测数据时的关键检查项：
  • few-shot 数量：0-shot / 5-shot / 8-shot 结果差异显著，必须对齐
  • 是否使用 CoT：Chain-of-Thought 可大幅提升推理分数
  • 评测框架：不同框架（lm-eval-harness / OpenCompass / 自研）的 prompt 格式差异导致分数不同
  • 数据污染：测试集是否已泄露到训练数据中
  • 报告选择性偏差：厂商往往只报告自家模型表现最好的指标

总结

图 11：大模型评测指标速查表——按模态分类，一览核心指标、公式与 Benchmark。
一句话总结：没有单一指标能全面衡量一个大模型。 好的评测需要多维度覆盖（知识/推理/代码/数学/多模态/安全）、 多策略结合（自动指标 + 人类评估 + Arena）、 并对评测条件保持透明（few-shot / CoT / 框架 / 数据污染）。

评测体系本身也在快速演化：静态 Benchmark 正逐步被动态评测（LiveBench）和人类偏好平台（Arena）补充； 单纯的准确率正被更细粒度的能力诊断取代；而对数据污染和评测公平性的关注，正在推动整个领域走向更成熟的评测范式。
