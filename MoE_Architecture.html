MoE 架构详解
混合专家模型的原理与实践

用 1/4 的计算成本获得 4 倍参数量的模型能力
Mixture of Experts Sparse Activation Router / Gating Load Balancing Expert Parallelism

一、什么是 MoE？

MoE（Mixture of Experts，混合专家）是一种稀疏激活的模型架构： 将 Transformer 的 FFN 层替换为多个并行的"专家"（Expert）FFN， 每个 token 只激活其中少数几个专家，而非使用全部参数。

核心价值：MoE 让模型拥有巨大的总参数量（存储更多知识）， 同时保持与小模型相当的推理计算量（每个 token 只用少数专家）。 这打破了"更多参数 = 更多计算"的线性关系。
图 1：Dense FFN（左）vs MoE FFN（右）。Dense 模型中所有 token 通过同一个 FFN； MoE 模型中 Router 为每个 token 选择 Top-2 个专家，只有被选中的专家参与计算。 总参数量是 Dense 的 8 倍，但每个 token 的计算量几乎相同。
图 2：MoE 在大语言模型中的发展时间线。从 2021 年 Google 的 Switch Transformer 到 2025 年 Meta 的 Llama 4 Maverick。

二、MoE 架构详解

2.1 整体结构

MoE 模型的结构与标准 Transformer 几乎相同——唯一的区别是将部分或全部层的 FFN 替换为 MoE 层。 注意力层完全不变。

图 3：完整的 MoE Transformer Block。上半部分（Self-Attention）与标准 Transformer 完全相同； 下半部分将单一 FFN 替换为 Router + N 个专家 FFN + 可选的共享专家。

2.2 核心公式

MoE(h) = ∑i ∈ TopK gi(h) · Experti(h)

g(h) = Softmax(h · Wr)   →   保留 Top-k 个，其余设为 0 并重新归一化

其中：

  • h：当前 token 的隐藏状态 ∈ Rd
  • Wr：Router 权重矩阵 ∈ Rd × Ne（Ne = 专家数）
  • gi(h)：token h 对专家 i 的路由权重（Top-k 选择后重新归一化）
  • Experti：第 i 个专家，结构与标准 SwiGLU FFN 完全相同

三、Router（路由 / 门控网络）

3.1 工作流程

图 4：Router 工作流程示例（Top-2）。Token 的隐藏状态经线性投影得到 8 个专家的 logits， Softmax 后选出概率最高的 2 个专家（E0=35%，E1=25%），重新归一化后作为加权系数。

3.3 负载均衡

如果 Router 将大部分 token 路由到少数"热门"专家，会导致：(1) 这些专家的 GPU 过载； (2) 其他专家得不到训练，逐渐退化。

图 5：负载均衡的效果。左图：无均衡时专家负载极不均匀（E0 承担 35% 的 token）； 右图：加入负载均衡损失后，各专家的 token 分配趋于均匀。
Lbalance = α · Ne · ∑i fi · Pi

fi = 专家 i 实际接收的 token 比例,   Pi = 所有 token 对专家 i 的平均路由概率

这个辅助负载均衡损失与主 loss 一起优化，鼓励 Router 均匀分配 token。 超参数 α 控制均衡力度（通常 0.01-0.1）。

Token Dropping：当某个专家接收的 token 超过其容量因子（capacity factor）时， 溢出的 token 直接走残差通道跳过 MoE 层。这保证了计算的可预测性， 但可能导致部分 token 得不到专家处理。现代模型（如 DeepSeek-V3）通过无 Token Dropping 的设计避免此问题。

四、共享专家与细粒度 MoE

4.1 共享专家（Shared Expert）

DeepSeek-V2 引入了共享专家机制：除了 N 个路由专家外， 额外设置 1-2 个始终激活的共享专家，所有 token 都通过它们。

MoE(h) = SharedExpert(h) + ∑i ∈ TopK gi(h) · Experti(h)
共享专家的价值： (1) 捕获所有 token 共享的通用知识（如语法结构、常见模式），路由专家专注于领域知识； (2) 稳定训练——即使路由不完美，共享专家也保证每个 token 有基本的处理； (3) 减少专家间的冗余——通用能力集中在共享专家，路由专家可以更好地特化。

4.2 细粒度 MoE

DeepSeek-V3 使用 256 个路由专家 + 1 个共享专家，每 token 激活 Top-8 个路由专家。 相比 Mixtral 的 8 个大专家，这种"更多更小的专家"设计带来更精细的路由选择和更好的负载均衡。

五、专家特化与知识分布

研究发现，MoE 模型中的专家会自然地产生领域特化—— 某些专家更擅长数学推理，某些擅长代码生成，某些处理多语言文本。 这种特化是通过训练自动涌现的，而非手动设计。

图 6：专家特化模式（示意图）。不同专家在不同任务类别上的路由权重分布不同—— Expert 0 擅长数学和代码，Expert 3 擅长翻译，Expert 5 是通才。

六、主流 MoE 模型详细介绍

图 7：主流 MoE 模型的总参数量 vs 激活参数量对比。DeepSeek-V3 拥有 671B 总参数， 但每个 token 只激活 37B——比 LLaMA-3 70B 的计算成本还低。

Mixtral 8x7B — 开源 MoE 的里程碑

Mistral AI | 2023.12 | 开源
总参数: 46.7B 激活参数: 12.9B 专家: 8 个 Top-k: 2 上下文: 32K

架构：32 层 Transformer，每层的 FFN 被替换为 8 个完整 FFN 专家。 每个专家与 Mistral 7B 的 FFN 结构相同（SwiGLU，中间维度 14336）。 使用 GQA（8 个 KV 头）和滑动窗口注意力（w=4096）。

创新：(1) 首个高质量开源 MoE LLM，性能匹配 LLaMA-2 70B 但推理速度快 6 倍； (2) 证明了 MoE 在中等规模也非常有效——不一定需要千亿参数才能受益。

性能：在 MMLU（70.6%）、GSM8K（74.4%）、HumanEval（40.2%）等基准上 匹配甚至超越 LLaMA-2 70B，但推理时只激活 12.9B 参数。

DeepSeek-V2 — MLA + Fine-grained MoE

DeepSeek AI | 2024.05 | 开源
总参数: 236B 激活参数: 21B 路由专家: 160 共享专家: 2 Top-k: 6

架构创新：(1) Multi-head Latent Attention (MLA)—— 用低秩压缩替代 GQA，KV Cache 降至标准 MHA 的 5-13%； (2) 细粒度 MoE——160 个小专家 + 2 个共享专家， 相比 Mixtral 的 8 个大专家，路由更精细、负载更均衡； (3) Device-Limited Routing——限制每个 token 最多路由到 M 个设备上的专家， 减少 All-to-All 通信。

性能：在多数基准上与 LLaMA-3 70B 持平，但推理成本只有约 1/3。 训练成本仅为 LLaMA-3 70B 的约 1/10。

DeepSeek-V3 — 671B 超大 MoE

DeepSeek AI | 2024.12 | 开源
总参数: 671B 激活参数: 37B 路由专家: 256 共享专家: 1 Top-k: 8 训练: 14.8T tokens

架构：61 层，MLA 注意力 + 256 路由专家 MoE。 创新包括：(1) Multi-Token Prediction (MTP)——同时预测多个未来 token， 提升训练效率和推理速度（通过投机解码）； (2) 无辅助损失的负载均衡——用动态偏置替代辅助 loss， 避免辅助 loss 对主任务的干扰； (3) FP8 混合精度训练——在 2048 块 H800 GPU 上完成训练。

性能：在 MMLU (88.5%)、MATH (90.2%)、Codeforces (51.6%) 等基准上 达到 GPT-4o 和 Claude 3.5 Sonnet 水平，训练成本仅约 557 万美元。

Qwen2.5-MoE — 高效小型 MoE

Alibaba Qwen Team | 2025.01 | 开源
总参数: 57.4B 激活参数: 3.7B 路由专家: 60 共享专家: 4 Top-k: 4

特点：(1) 极高的参数效率——3.7B 激活参数达到 Qwen2.5-7B（Dense）的性能； (2) 4 个共享专家，比 DeepSeek 更多，强化通用知识基座； (3) 支持 128K 上下文窗口。

Llama 4 Maverick — Meta 的 MoE 探索

Meta AI | 2025.04 | 开源
总参数: 400B 激活参数: 17B 路由专家: 128 Top-k: 1 上下文: 1M (10M 可选)

特点：(1) Meta 首个公开的 MoE 模型，标志着 MoE 从"小众技术"变为行业标配； (2) Top-1 路由——每 token 只激活 1 个专家，极致稀疏； (3) 原生多模态支持（文本 + 图像）； (4) 超长上下文 1M tokens。

八、MoE 的优势与挑战

✓ 优势

  • 参数效率：用远低于总参数量的计算量获得大模型的知识容量
  • 推理速度：激活参数少 → 每 token 计算量小 → 延迟低、吞吐高
  • 可扩展性：可以通过增加专家数扩展模型，计算量几乎不增加
  • 专家特化：不同专家自然分化为不同领域的"专家"
  • 训练效率：相同计算预算下，MoE 可以训练更大的模型，获得更好的性能

✗ 挑战

  • 显存占用大：虽然激活参数少，但全部参数都要加载到 GPU
  • 通信开销：Expert Parallelism 需要 All-to-All 通信，延迟较高
  • 负载均衡：Router 容易出现"赢家通吃"，需要额外的均衡机制
  • 训练不稳定：稀疏路由引入离散决策，训练初期容易震荡
  • 微调困难：小数据集可能只训练到部分专家，其余专家退化
  • 批量推理效率：不同请求激活不同专家，GPU 计算不规则
显存 vs 计算的权衡：MoE 模型的推理需要将全部参数加载到 GPU （DeepSeek-V3 需要 ~1.3 TB FP16），即使每个 token 只用其中 6%。 这意味着 MoE 推理需要大量 GPU 来存放参数，但每张 GPU 的计算利用率较低。 这是 MoE 模型部署的核心矛盾，也是推动量化（INT4/INT8）和 offloading 技术发展的重要动力。

九、MoE 的并行与通信

MoE 模型的训练和推理引入了一种专有的并行方式——专家并行（Expert Parallelism, EP）。

1

Expert Parallelism

将 N 个专家分布到不同 GPU。每个 GPU 持有 N/EP_size 个专家。 Token 通过 All-to-All 通信路由到目标专家所在的 GPU。

2

EP + TP 组合

单个专家内部可以再做张量并行（TP）。常见配置：EP=8（跨节点），TP=4（节点内）。 注意力层仍用标准 TP。

3

EP + PP 组合

不同层组放在不同 pipeline 阶段。MoE 层和非 MoE 层可能在不同阶段， 需要平衡计算量。

4

通信优化

分层 All-to-All（先节点内再节点间）、通信-计算重叠、 限制跨节点路由（Device-Limited Routing）等。

十、总结与趋势

MoE 架构的演化呈现出几个清晰的趋势：

  1. 从少量大专家到大量小专家：Mixtral（8 个大专家）→ DeepSeek-V3（256 个小专家）。 更细粒度的专家带来更好的路由灵活性和负载均衡。
  2. 共享专家成为标配：从无共享（Mixtral）到 1-4 个共享专家（DeepSeek/Qwen）， 通用知识与领域知识的解耦成为共识。
  3. 激活率越来越低：从 28%（Mixtral）到 4%（Llama 4）， 模型参数越来越大，但每个 token 的计算量保持在等效 7B-37B 的水平。
  4. 注意力层也在创新：MoE 往往与 GQA、MLA 等高效注意力结合， 在 KV Cache 和计算量两个维度同时优化。
  5. MoE 成为行业标配：从 Google 内部方案到 Mixtral 开源突破， 再到 Meta、阿里、DeepSeek 全面采用——MoE 已从"可选优化"变为"主流架构"。
一句话理解 MoE： 让模型拥有"百科全书"般的参数量来存储海量知识， 但每次回答问题时只翻阅最相关的几页—— 用稀疏激活实现"知识广度"与"计算效率"的兼得。
