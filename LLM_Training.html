一、预训练目标与损失函数

1.1 Next Token Prediction（NTP）

几乎所有 Decoder-only 的大语言模型（GPT、LLaMA、Qwen、DeepSeek 等）都采用相同的预训练目标： 给定前文，预测下一个 token。这个看似简单的目标，在足够大的数据和模型规模下， 能涌现出推理、翻译、编程等多种能力。

L(θ) = − (1/T) ∑t=1T log Pθ(xt | x1, x2, ..., xt−1)

其中 T 是序列长度，θ 是模型参数，xt 是第 t 个 token。 训练的目标是最小化整个训练语料上的交叉熵损失。

图 2：Next Token Prediction 训练原理。输入和目标错位一个 token，每个位置独立计算损失。

1.2 为什么 NTP 如此有效？

1

隐式多任务学习

预测下一个 token 要求模型同时理解语法、语义、逻辑、世界知识——一个目标隐式地训练了无数能力。

2

数据效率极高

每条长度为 T 的序列产生 T 个训练样本，无需人工标注。互联网上有几乎无限的无标注文本。

3

与推理天然一致

训练目标（预测下一 token）和推理过程（自回归生成）完全一致，无 train/test mismatch。

4

可扩展性强

Scaling Laws 证明：增加数据和参数，NTP 损失可以持续、可预测地下降，带来能力跃迁。

二、预训练数据工程

数据是预训练的燃料。数据的质量、规模和配比对最终模型能力的影响，往往超过模型架构本身。 现代 LLM 的预训练数据量通常在 1T ~ 15T+ tokens 之间。

三、各阶段训练数据详解

大模型的训练分为预训练、监督微调（SFT）、对齐训练（RLHF/DPO）三大阶段， 每个阶段对数据的数量、质量、格式、来源有截然不同的需求。 数据设计直接决定了模型的知识广度、指令遵循能力和安全性。本节将系统介绍各阶段的训练数据。

3.1.1 数据来源与获取方式

预训练数据是模型知识的根基，来源广泛且规模庞大。以下是主要的数据来源及其获取方式：

图 6：预训练数据来源全景图。网页文本是最大来源，代码数据对推理能力至关重要，书籍和学术数据提供高质量长文本。

3.1.2 数据质量控制与设计细节

预训练数据的核心设计原则：
  • 多样性优先：覆盖尽可能多的领域、语言、格式，避免能力偏科
  • 去重是关键：重复数据会导致模型记忆特定文本，降低泛化能力。MinHash 去重通常可去除 30%~50% 数据
  • 质量与规模的平衡：不是越多越好——低质量数据（SEO 垃圾、广告、乱码）会"污染"模型
  • 数据配比需要实验搜索：代码比例增加可提升推理能力，但过高会降低自然语言流畅度
  • 安全过滤：移除有毒内容（仇恨言论、个人信息、CSAM），部分模型使用分类器自动过滤
  • 数据新鲜度：Web 数据有时效性，通常采用多个时间段的 Common Crawl 快照混合

以下是影响预训练数据质量的关键清洗规则（以 RefinedWeb / FineWeb 的最佳实践为代表）：

3.2 SFT 微调数据详解

3.2.1 SFT 数据的格式与构建

SFT 数据是结构化的（指令, 回答）对，通常以多轮对话格式组织。 数据质量直接决定模型的指令遵循能力和回答质量。

图 8：SFT 数据构建流程。数据来源包括人工标注、强模型蒸馏、开源数据集和自我迭代，经过严格质量审核后覆盖多种任务能力。

3.2.2 SFT 数据的关键设计原则

1

多样性 > 数量

LIMA（2023）证明仅 1000 条精选数据即可获得强 SFT 效果。覆盖尽可能多的任务类型和难度等级，比堆积数量更重要。

2

回答质量标准化

建立统一的回答质量标准：准确性、详细度、格式规范、安全性。标注员间一致性（IAA）通常要求 Cohen's κ > 0.7。

3

难度梯度设计

数据应涵盖从简单（"什么是 Python？"）到复杂（"设计一个分布式缓存系统"）的任务梯度，避免模型只会回答简单问题。

4

拒绝样本 (Refusal)

~5%~10% 的数据应为"安全拒绝"样本：模型对有害请求礼貌拒绝。这是模型安全的第一道防线。

3.2.3 主流模型 SFT 数据详解

3.3 对齐训练（RLHF/DPO）数据详解

3.3.1 偏好数据的格式与标注

对齐训练的核心数据格式为偏好对（Preference Pair）： 给定同一提示（prompt），标注者在两个（或多个）回答中选择更好的一个。 标注的维度通常包括：有用性（helpfulness）、诚实性（honesty）、安全性（harmlessness）。

图 9：偏好数据标注与对齐训练数据流。从 prompt 收集、多回答生成、人工偏好标注到质量校验，形成 (prompt, chosen, rejected) 三元组。

3.3.2 对齐数据的类型与构建方式

数据类型 格式 用途 规模 获取方式
偏好对 (prompt, chosen, rejected) 训练 RM / DPO 100K~2M 对 标注员从模型输出中选择偏好
多维评分 (prompt, response, score1..n) 训练多维度 RM 50K~500K 条 标注员对每个维度独立打分
红队攻击数据 (attack_prompt, safe_response) 安全对齐 10K~100K 条 红队人员构造攻击 + 标注安全回复
规则验证数据 (problem, response, reward) RLVR / GRPO 100K~1M 条 用规则/代码自动验证（如数学答案是否正确）
AI 反馈数据 (prompt, response, AI_score) RLAIF（AI 替代人类反馈） 100K~5M 条 强模型作为评判者对回答打分

对齐数据的演进趋势：
  • 从纯人工标注到 AI 辅助（RLAIF）：用强模型（如 GPT-4）作为评判者，大幅降低标注成本，Constitutional AI（Anthropic）是这一思路的代表
  • 从偏好标注到规则验证（RLVR）：DeepSeek-R1 开创了用代码执行结果、数学答案正误等可验证信号替代人类主观偏好，在推理任务上效果更好
  • 从离线 DPO 到在线 DPO（Online DPO）：Qwen 等模型在 DPO 训练过程中持续生成新的偏好对，而非一次性使用静态数据集
  • 从单一奖励到多维度奖励：LLaMA-2 开创分别训练 Helpfulness RM 和 Safety RM 的做法，比单一 RM 更精确地平衡有用性和安全性

图 10：主流模型各训练阶段数据规模全景。可以看到从 LLaMA-1 到最新模型，预训练数据量增长 10 倍以上，SFT 和对齐方法也在快速演进。
训练数据的法律与伦理挑战：
  • 版权问题：使用网页和书籍数据引发的版权诉讼不断增加（如 NYT vs. OpenAI），推动模型厂商转向更多授权数据和合成数据
  • 数据隐私：训练数据中的个人可识别信息（PII）需严格脱敏处理，GDPR 等法规对数据使用提出合规要求
  • 数据偏见：网页数据天然存在语言、文化、性别等偏见，需要在数据层面和训练层面双重去偏
  • 数据污染：训练数据可能包含评测集的答案（data contamination），导致 benchmark 分数虚高

四、核心训练超参数与策略

4.1 学习率调度（Learning Rate Schedule）

学习率是预训练中最关键的超参数。现代 LLM 通常采用 Warmup + Cosine Decay 调度策略。

图 11：Warmup + Cosine Decay 学习率调度。先线性增长到 Peak LR，再以余弦曲线衰减到 Min LR（通常为 Peak 的 10%）。

4.2 核心超参数一览

超参数 含义 典型值 说明
Peak Learning Rate 最高学习率 1.5e-4 ~ 3e-4 模型越大，LR 通常越小
Batch Size 每步训练的 token 数 4M ~ 60M tokens 通常随训练逐步增大（Warmup）
Sequence Length 训练序列长度 4096 ~ 131072 部分模型分阶段扩展长度
Optimizer 优化器 AdamW β₁=0.9, β₂=0.95, ε=1e-8
Weight Decay 权重衰减 0.1 正则化，防止过拟合
Gradient Clipping 梯度裁剪 1.0 防止梯度爆炸，稳定训练
Warmup Steps 学习率预热步数 2000 从 0 线性增长到 Peak LR
Precision 训练精度 BF16 / FP8 混合精度训练节省显存

4.3 Batch Size Warmup 策略

现代 LLM 训练常采用渐增 Batch Size策略：训练初期使用较小的 batch（如 4M tokens）， 随训练进行逐步增大到最终值（如 32M tokens）。

直觉理解：训练初期模型参数随机，小 batch 带来的噪声梯度有利于探索损失面上的方向； 训练后期模型接近收敛，大 batch 提供更稳定的梯度估计，帮助精细调整。 同时，渐增 batch 也使训练初期的吞吐量更高（数据并行度更灵活）。

五、分布式训练技术

一个 70B 参数的模型以 BF16 存储需要约 140 GB 显存，加上优化器状态和梯度需要 ~1 TB 显存。 单张 GPU（80GB）远远不够，必须依赖分布式训练。

5.1 三大并行策略

图 12：三种并行策略对比。实际训练通常采用"3D 并行"——同时使用 DP + TP + PP 的组合。

5.2 混合精度训练

现代 LLM 训练普遍采用混合精度（Mixed Precision）：前向和反向传播使用 BF16/FP16 计算（2 字节/参数）， 优化器状态保持 FP32（4 字节/参数），更新时在 FP32 空间完成后再转回低精度。

精度格式 位宽 数值范围 使用场景
FP32 32 bit 大范围 + 高精度 优化器状态（Master Weights）
BF16 16 bit 与 FP32 同范围，精度略低 前向/反向计算（主流选择）
FP16 16 bit 范围小，需 Loss Scaling 前向/反向计算（旧方案）
FP8 (E4M3/E5M2) 8 bit 极小范围 DeepSeek-V3 等前沿模型的训练
DeepSeek-V3 的突破：在预训练中成功使用了 FP8 混合精度训练， 将计算效率提升约 1.5 倍。这是首个公开证实 FP8 训练可行的超大规模模型， 显著降低了训练成本（14.8T tokens 仅用 2.788M H800 GPU 小时 ≈ $5.5M）。

5.3 显存分析

训练一个参数量为 Φ 的模型，显存消耗如下（以 BF16 混合精度 + AdamW 为例）：

显存 ≈ 2Φ（模型参数 BF16）+ 2Φ（梯度 BF16）+ 4Φ（FP32 master weights）+ 8Φ（Adam 状态 m + v）= 16Φ 字节

以 70B 模型为例: 16 × 70 × 10⁹ = 1.12 TB → 需要至少 14 张 A100 (80GB) 仅放模型状态

六、训练稳定性与异常处理

大模型预训练动辄耗时数月、花费数百万美元。训练中的不稳定（如 Loss Spike、NaN、发散） 一旦未被及时发现和处理，就可能浪费大量计算资源。

6.1 Loss Spike（损失尖刺）

图 13：Loss Spike 现象。训练损失突然飙升后自行恢复（小 Spike），或持续上升导致发散（致命 Spike）。

6.2 应对策略

1

梯度裁剪（Gradient Clipping）

限制梯度的最大范数（通常 clip=1.0）。这是几乎所有 LLM 训练的标配，能有效防止梯度爆炸。

2

使用 BF16 而非 FP16

BF16 与 FP32 同范围（8 位指数），不易溢出；FP16 范围窄（5 位指数），需要 Loss Scaling。

3

回滚重训（Rollback）

遇到严重 Spike 时，回退到最近的 Checkpoint，跳过有问题的数据 batch 重新训练。

4

z-loss 正则化

PaLM 提出的方法：在 Softmax 之前的 logits 上添加 z-loss 惩罚项，防止 logits 过大。

z-loss = α · log2( ∑j exp(zj) )

α = 1e-4；鼓励 logits 不要过大，减少 Softmax 数值不稳定

6.3 Checkpoint 策略

Checkpoint 是训练的"保险单"： 大模型训练通常每 500~2000 步保存一次完整 Checkpoint（模型参数 + 优化器状态 + LR 调度器 + 数据进度）。 一个 70B 模型的完整 Checkpoint 约 1~2 TB。训练期间通常保留最近 3~5 个 Checkpoint + 若干里程碑 Checkpoint。

七、Scaling Laws —— 大模型训练的"路线图"

7.1 Kaplan Scaling Law (OpenAI, 2020)

OpenAI 的 Kaplan 等人首先发现：模型的测试 Loss 与模型参数量 N、训练数据量 D、训练计算量 C 之间存在幂律关系。

L(N) ∝ N−0.076   |   L(D) ∝ D−0.095   |   L(C) ∝ C−0.050

在三者之间合理分配资源，可以最小化给定计算预算下的 Loss

7.2 Chinchilla Scaling Law (DeepMind, 2022)

Hoffmann 等人在 Training Compute-Optimal Large Language Models 中进一步发现： 给定固定的计算预算 C，参数量和数据量应该等比例增长—— 即训练 token 数 D ≈ 20 × 参数量 N。

图 14：从 Chinchilla 最优到 Over-training。现代实践往往刻意过训练（200×+），用更多数据训练较小模型，因为推理成本 >> 训练成本。
行业现状：Chinchilla Law 的"数据 = 20× 参数"只是 训练计算最优。 实际部署时，推理成本远高于训练成本（模型要持续服务数百万用户）。 因此，当前主流做法是"Over-training"——用更多数据训练较小的模型， 获得更好的推理性价比。LLaMA-3 70B 训练了 15T tokens（214× 参数量），远超 Chinchilla 最优的 20×。

八、监督微调（SFT）

8.1 SFT 的目标与原理

预训练后的 Base Model 是一个优秀的"文本续写器"，但不会遵循指令、不会以对话格式回复。 SFT（Supervised Fine-Tuning）的目标是教模型"如何做一个好助手"—— 使用人工编写的（指令, 回答）对进行有监督训练。

图 15：SFT 训练的核心：只在 Assistant 回复部分计算损失，System 和 User 部分被 mask 掉，防止模型"学会提问"而非"学会回答"。

8.2 SFT 的关键实践

维度 典型值 说明
数据量 10K ~ 10M 条 质量 >> 数量；少量高质量数据优于大量低质量数据
学习率 1e-5 ~ 5e-5 比预训练低 ~10 倍，防止遗忘预训练知识
训练轮数 2~5 epochs 通常 2~3 轮即可，过多会过拟合
数据来源 人工标注 + 合成 用强模型（GPT-4）合成数据已成为主流
训练耗时 数小时~数天 比预训练快 100~1000 倍

8.3 参数高效微调（PEFT）

全参数 SFT 需要修改所有参数，对显存要求高。LoRA（Low-Rank Adaptation）是最流行的 PEFT 方法，只训练低秩增量矩阵：

W' = W + ΔW = W + B · A

W ∈ Rd×d（冻结），A ∈ Rr×d，B ∈ Rd×r（可训练），r << d（如 r=8~64）
可训练参数量仅为全参数的 ~0.1%~1%，显存需求大幅降低

九、对齐训练 —— 让模型安全、有用、诚实

9.1 RLHF（Reinforcement Learning from Human Feedback）

SFT 模型能遵循指令，但输出质量参差不齐。RLHF 通过人类偏好反馈进一步优化模型—— "告诉模型哪个回答更好"。完整的 RLHF 分三步：

Step 1
训练奖励模型 (RM)
→
Step 2
PPO 强化学习优化
→
Step 3
迭代收集 & 再训练
图 16：RLHF 完整流程。先训练奖励模型，再用 PPO 强化学习优化 SFT 模型，KL 惩罚防止过度优化。

9.2 DPO（Direct Preference Optimization）

DPO（Rafailov et al., 2023）跳过了显式训练奖励模型的步骤，直接用偏好数据优化策略模型。 它将 RLHF 的优化目标转化为一个简洁的二分类损失：

LDPO(θ) = − E(x,yw,yl) [ log σ( β · ( log(πθ(yw|x) / πref(yw|x)) − log(πθ(yl|x) / πref(yl|x)) ) ) ]

yw = 人类偏好的好回答, yl = 人类不偏好的差回答, πref = SFT 参考模型

9.3 GRPO（Group Relative Policy Optimization）

DeepSeek 在 R1 模型中提出的 GRPO，核心创新是去掉了独立的奖励模型， 而是在一组采样结果内部通过相对排序来计算优势函数。这大幅简化了训练流程。

9.4 对齐方法对比

方法 需要奖励模型？ 训练复杂度 效果 代表模型
RLHF (PPO) 是 高（4 个模型同时在线） 强 GPT-4, Claude
DPO 否 低（与 SFT 相当） 接近 RLHF Zephyr, LLaMA-3
GRPO 否 中 强（尤其推理任务） DeepSeek-R1
KTO 否 低 良好 部分开源模型

十一、长上下文与多阶段训练

11.1 多阶段训练策略

现代 LLM 通常不是"一次性训练到底"，而是采用多阶段训练策略， 不同阶段使用不同的数据配比、学习率和上下文长度。

图 18：典型的多阶段训练流程。通用预训练奠定基础，长上下文阶段扩展窗口，退火阶段用高质量数据精细打磨。

11.2 长上下文训练的关键技术

1

RoPE 频率缩放

通过调整 RoPE 的 base frequency（如从 10000 增大到 500000），使位置编码能外推到更长的序列。

2

渐进式长度扩展

不直接从 4K 跳到 128K，而是分阶段扩展：4K → 32K → 128K，每阶段用较少的数据适应新长度。

3

Ring Attention / Sequence Parallel

将超长序列的注意力计算分散到多张 GPU，每张 GPU 只处理序列的一部分，通过环形通信交换 KV。

4

长文本数据采集

训练数据中需包含足够的长文档（书籍、论文、代码仓库）。只靠短文本拼接的"假长文"效果很差。

十二、训练成本与效率

12.1 训练成本估算

预训练的计算量可以用一个简单的公式估算：

C ≈ 6 · N · D   (FLOPs)

N = 参数量, D = 训练 token 数; 6 = 前向(2ND) + 反向(4ND) 的系数
模型 参数量 训练 Token 数 估算 FLOPs 估算 GPU·h 估算成本
LLaMA-2 70B 70B 2T 8.4×10²³ ~1.7M A100·h ~$3.4M
LLaMA-3 70B 70B 15T 6.3×10²⁴ ~6.4M H100·h ~$20M
LLaMA-3 405B 405B 15T 3.6×10²⁵ ~30M H100·h ~$100M+
DeepSeek-V3 671B MoE (37B act.) 14.8T ~5.5×10²⁴ * 2.788M H800·h ~$5.5M

* MoE 激活参数仅 37B，计算量远低于同规模 Dense 模型

效率启示：DeepSeek-V3 用 $5.5M 训练了 671B MoE 模型，性能媲美 GPT-4 和 LLaMA-3 405B， 成本仅为后者的 1/10~1/20。这得益于 MoE 架构（少激活参数）、FP8 训练、高效并行策略的三重优化。

12.2 MFU（Model FLOPs Utilization）

MFU 衡量训练过程中 GPU 的实际利用效率。理论峰值的百分比越高越好。

MFU = 实际训练 FLOPs / (GPU 理论峰值 FLOPs × 训练时间)
训练规模 典型 MFU 说明
小规模（单机 8 卡） 50~60% 通信开销小，利用率高
中规模（~256 GPU） 40~55% 跨机通信成为瓶颈
超大规模（1000+ GPU） 30~45% Pipeline Bubble + 通信开销
DeepSeek-V3 (2048 GPU) ~52% 业界领先，归功于高效并行设计

一句话总结：大模型训练是一场数据、算力、工程和算法的系统工程。 预训练用海量数据和计算教会模型"理解世界"，SFT 教会模型"听从指令"，对齐训练教会模型"做个好助手"。 在这条路上，数据质量 > 数据数量，训练效率 > 训练规模， 而 Scaling Laws 为整个过程提供了可预测的路线图。
