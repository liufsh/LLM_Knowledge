摘要

本文介绍了 DeepSeek-V4 系列的预览版本，包含两个强大的 Mixture-of-Experts (MoE) 语言模型：DeepSeek-V4-Pro（1.6T 总参数，49B 激活）和 DeepSeek-V4-Flash（284B 总参数，13B 激活），均支持 100万 token 的上下文长度。

三大核心创新：
  1. 混合注意力架构：结合压缩稀疏注意力 (CSA) 和重压缩注意力 (HCA)，大幅提升长上下文效率
  2. 流形约束超连接 (mHC)：增强传统残差连接，改善训练稳定性
  3. Muon 优化器：加速收敛，提升训练稳定性

在百万 token 上下文场景下，DeepSeek-V4-Pro 的单 token 推理 FLOPs 仅为 DeepSeek-V3.2 的 27%，KV 缓存仅为其 10%。DeepSeek-V4-Pro-Max（最大推理模式）重新定义了开源模型的最优水平，在核心任务上超越其前代模型。

1. 引言

推理模型的兴起开创了测试时扩展的新范式，为大语言模型 (LLM) 带来了显著的性能提升。然而，这种扩展范式受到 vanilla 注意力机制二次计算复杂度的根本性限制，为超长上下文和推理过程造成了瓶颈。

为突破超长上下文的效率壁垒，DeepSeek 开发了 DeepSeek-V4 系列：

  • DeepSeek-V4-Pro：1.6T 总参数（49B 激活）
  • DeepSeek-V4-Flash：284B 总参数（13B 激活）

通过架构创新，DeepSeek-V4 系列在处理超长序列时实现了计算效率的飞跃，原生支持百万 token 的上下文长度。

相比 DeepSeek-V3 架构的关键升级：
  • 设计了结合 CSA 和 HCA 的混合注意力机制，大幅提升长上下文效率
  • 引入流形约束超连接 (mHC) 替代传统残差连接，增强建模能力
  • 采用 Muon 优化器，加速收敛并改善训练稳定性
  • 沿用 DeepSeekMoE 框架和多 Token 预测 (MTP) 策略
基础设施优化：
  • 设计融合通信与计算的 MoE 单一融合内核
  • 采用 TileLang 领域特定语言 (DSL) 开发高效内核
  • 提供批次不变和确定性内核库
  • 引入 FP4 量化感知训练
  • 扩展自动微分框架支持张量级 checkpoint
  • 设计异构 KV 缓存结构支持磁盘存储

核心评估结果摘要

  • 知识：DeepSeek-V4-Pro-Max 在 SimpleQA 和 Chinese-SimpleQA 上显著超越开源模型，在 MMLU-Pro 等教育知识评测上展现领先优势
  • 推理：DeepSeek-V4-Pro-Max 在标准推理任务上超越 GPT-5.2 和 Gemini-3.0-Pro，与 GPT-5.4 和 Gemini-3.1-Pro 差距很小
  • Agent：在公开 benchmark 上与 Kimi-K2.6 和 GLM-5.1 等顶级开源模型持平，内部评估超越 Claude Sonnet 4.5
  • 长上下文：在百万 token 上下文中表现强劲，在学术 benchmark 上甚至超越 Gemini-3.1-Pro

2. 架构

DeepSeek-V4 系列保留了 Transformer 架构和多 Token 预测 (MTP) 模块，同时在架构和优化上引入了多项关键升级。

Figure 2 | DeepSeek-V4 系列的整体架构。注意力层使用混合 CSA 和 HCA，前馈层使用 DeepSeekMoE，通过 mHC 增强残差连接。

2.1 从 DeepSeek-V3 继承的设计

Mixture-of-Experts

DeepSeek-V4 继续采用 DeepSeekMoE 范式，使用细粒度路由专家和共享专家。与 V3 的区别包括：

  • 路由亲和力分数的激活函数从 Sigmoid(·) 改为 Sqrt(Softplus(·))
  • 采用无辅助损失的负载均衡策略
  • 移除了路由目标节点数量的约束
  • 前几层的密集 FFN 替换为使用 Hash 路由的 MoE 层

Multi-Token Prediction

与 DeepSeek-V3 相同，设置 MTP 模块和目标，策略不做修改。

2.2 流形约束超连接 (mHC)

DeepSeek-V4 引入流形约束超连接 (mHC) 来增强相邻 Transformer 块之间的残差连接。相比朴素的超连接 (HC)，mHC 的核心思想是将残差映射约束到特定的流形上，从而增强层间信号传播的稳定性。

标准超连接

标准 HC 通过因子 nhc 扩展残差流的宽度，从 ℝd 到 ℝnhc×d。HC 引入三个线性映射：输入映射 Al、残差变换 Bl 和输出映射 Cl，残差状态更新公式为：

Xl+1 = BlXl + ClFl(AlXl)

流形约束残差映射

mHC 的核心创新是将残差映射矩阵 Bl 约束到双随机矩阵的流形（Birkhoff 多面体）上：

Bl ∈ M := {M ∈ ℝn×n | M1n = 1n, 1nTM = 1nT, M ≥ 0}

这一约束确保映射矩阵的谱范数 ‖Bl‖2 不超过 1，使得残差变换非扩张，增强数值稳定性。集合 M 在乘法下封闭，保证深层堆叠时的稳定性。

动态参数化

三个线性映射的参数通过动态（输入依赖）和静态（输入无关）两个分量动态生成。输入 Xl 先经过 RMSNorm 和展平得到 X̂l，然后通过可学习参数生成动态分量，加上静态偏置得到原始参数 Ãl、B̃l、C̃l。

参数约束

  • 输入和输出映射 Al、Cl：通过 Sigmoid 函数确保非负性和有界性
  • 残差映射 Bl：通过 Sinkhorn-Knopp 算法（迭代 tmax = 20 次）投影到双随机矩阵流形上

2.3 CSA 和 HCA 混合注意力

当上下文长度达到极端规模时，注意力机制成为模型的主要计算瓶颈。DeepSeek-V4 设计了两种高效注意力架构——压缩稀疏注意力 (CSA) 和重压缩注意力 (HCA)——并以交错混合方式使用，大幅降低长文本场景下的注意力计算成本。

2.3.1 压缩稀疏注意力 (CSA)

Figure 3 | CSA 的核心架构。将每 m 个 token 的 KV 条目压缩为一个，然后应用 DeepSeek 稀疏注意力进一步加速。滑动窗口 KV 条目与选择的压缩 KV 条目结合，增强局部细粒度依赖。

压缩 KV 条目：给定输入隐状态 H ∈ ℝn×d，CSA 首先计算两组 KV 条目 Ca, Cb 及其压缩权重 Za, Zb，然后将每 m 个 KV 条目压缩为一个，通过 softmax 加权的 Hadamard 乘积得到压缩条目 CComp，将序列长度压缩为原来的 1/m。

Lightning Indexer 稀疏选择：获得压缩 KV 条目后，CSA 应用 DSA 策略选择 top-k 个压缩 KV 条目进行核心注意力。通过低秩的 indexer 查询和 indexer 压缩键计算 index 分数，使用 top-k 选择器保留子集 CtSprsComp 用于后续核心注意力。

共享键值 MQA：在选择的稀疏 KV 条目上执行多查询注意力 (MQA)，每个压缩 KV 条目同时作为注意力键和值。采用分组输出投影策略减轻高维计算负担。

2.3.2 重压缩注意力 (HCA)

Figure 4 | HCA 的核心架构。以更大的压缩率（m' ≫ m）压缩 KV 缓存，但不使用稀疏注意力。同样引入滑动窗口 KV 条目增强局部依赖。

HCA 的压缩策略与 CSA 类似，但采用更大的压缩率 m'（≫ m）且不执行重叠压缩。HCA 将序列长度压缩为原来的 1/m'。HCA 同样使用共享键值 MQA 和分组输出投影。

2.3.3 其他细节

  • Query 和 KV 条目归一化：在核心注意力操作前对 query 和压缩 KV 条目执行 RMSNorm，防止注意力 logit 爆炸
  • 部分旋转位置编码 (RoPE)：对 query 和 KV 条目的最后 64 维应用 RoPE，同时在核心注意力输出上应用位置 −i 的 RoPE，使输出同时携带绝对和相对位置信息
  • 滑动窗口注意力分支：为严格保持因果性并建模局部依赖，为 CSA 和 HCA 引入滑动窗口注意力分支，生成 nwin 个未压缩 KV 条目
  • 注意力下沉 (Attention Sink)：设置可学习的 sink logit，允许各头自适应调整注意力分数总和

2.3.4 效率讨论

通过混合使用 CSA 和 HCA 以及低精度计算和存储优化，DeepSeek-V4 系列的注意力模块在长上下文场景下实现了显著的效率提升：

  • KV 缓存采用混合精度存储：RoPE 维度用 BF16，其余用 FP8，缓存大小减少近半
  • Lightning Indexer 内部的注意力计算使用 FP4 精度
  • 相比 DeepSeek-V3.2，选择更小的 attention top-k
  • 在百万 token 上下文设置中，KV 缓存可降至标准 BF16 GQA8 baseline 的约 2%

2.4 Muon 优化器

DeepSeek-V4 对大部分模块采用 Muon 优化器，因其更快的收敛速度和更好的训练稳定性。嵌入模块、预测头、mHC 的静态偏置和门控因子、RMSNorm 权重仍使用 AdamW 优化器。

Algorithm 1 | DeepSeek-V4 的 Muon 优化器算法。包含梯度计算、动量累积、Nesterov 技巧与混合 Newton-Schulz 正交化、RMS 重缩放以及权重衰减与更新。

混合 Newton-Schulz 迭代

用于近似正交化更新矩阵。分两阶段共 10 次迭代：前 8 步使用系数 (a,b,c) = (3.4445, −4.7750, 2.0315) 快速收敛，最后 2 步切换为 (2, −1.5, 0.5) 精确收敛。

避免注意力 logit 爆炸

DeepSeek-V4 的注意力架构允许直接对 query 和 KV 条目应用 RMSNorm，有效防止注意力 logit 爆炸，因此不需要 QK-Clip 技术。

3. 通用基础设施

3.1 专家并行中的细粒度通信-计算重叠

MoE 模型通过专家并行 (EP) 加速，但 EP 需要大量节点间通信。DeepSeek-V4 提出了细粒度的 EP 方案，将通信和计算融合为一个单一的流水线化内核。

Figure 5 | EP 方案与相关工作的对比。(a) 朴素方案：串行执行。(b) Comet：Dispatch 与 Linear-1 重叠，Combine 与 Linear-2 重叠（理论加速 1.42×）。(c) DeepSeek-V4 方案：将专家分割为波次调度，实现更细粒度的流水线重叠（理论加速 1.92×）。

通信延迟可被隐藏

分析表明，在 DeepSeek-V4 中单个 MoE 层内通信总时间少于计算时间。每 GBps 互联带宽可隐藏 6.1 TFLOP/s 的计算。当带宽满足此阈值后，继续增加带宽将收益递减。

开源 Mega-Kernel

基于 CUDA 的 mega-kernel 实现已作为 DeepGEMM 的组件 MegaMoE 开源。在 NVIDIA GPU 和华为 Ascend NPU 上验证，通用推理工作负载实现 1.50~1.73× 加速，延迟敏感场景可达 1.96× 加速。

3.2 TileLang 高效内核开发

DeepSeek-V4 采用 TileLang（一种领域特定语言 DSL）开发一组融合内核，替代大量细粒度的 Torch ATen 算子，在保持开发效率的同时实现最优性能。

关键特性包括：

  • Host Codegen：将主机端逻辑移入生成代码，减少 Python 调用开销至亚微秒级
  • Z3 SMT 求解器：集成 Z3 进行形式化整数分析，优化向量化、屏障插入和代码简化
  • 数值精度与比特级可复现性：默认禁用 fast-math 优化，支持 IEEE-754 兼容的精确舍入模式

3.3 批次不变与确定性内核库

为确保训练、后训练和推理流水线之间的比特级对齐，DeepSeek-V4 实现了端到端的批次不变和确定性内核。

批次不变性

  • 注意力：采用双内核策略，确保任何 token 的输出在批次中位置无关
  • 矩阵乘法：用 DeepGEMM 替代 cuBLAS，实现端到端批次不变

确定性

  • 注意力反向传播：为每个 SM 分配独立累加缓冲区，实现全局确定性求和
  • MoE 反向传播：设计 token 顺序预处理机制和缓冲区隔离策略
  • mHC 矩阵乘法：输出维度仅 24，分别输出各 split 部分后执行确定性归约

3.4 FP4 量化感知训练

在后训练阶段引入量化感知训练 (QAT)，对两个组件应用 FP4 (MXFP4) 量化：

  1. MoE 专家权重：GPU 内存的主要占用来源
  2. CSA Indexer 的 QK 路径：QK 激活以 FP4 缓存、加载和计算
FP4-to-FP8 反量化是无损的：因为 FP8 (E4M3) 比 FP4 (E2M1) 多 2 位指数位，动态范围更大。只要 FP4 量化块内最大与最小缩放因子的比值不超过阈值，就可以完全重用现有 FP8 训练框架。

3.5 训练框架

训练框架构建在 DeepSeek-V3 的基础设施之上，针对新架构组件做了适配：

3.5.1 Muon 的高效实现

  • 采用混合 ZeRO bucket 分配策略，限制 ZeRO 并行的最大规模
  • MoE 参数独立优化，所有专家的 down 投影矩阵和 up 投影矩阵与门控矩阵展平后均匀分布
  • MoE 梯度以 BF16 精度随机量化后同步，通信量减半

3.5.2 mHC 的高效实现

通过融合内核、选择性重计算策略和调整 DualPipe 1F1B 重叠方案，mHC 的 wall-time 开销仅为重叠 1F1B 流水线阶段的 6.7%。

3.5.3 长上下文注意力的上下文并行

设计两阶段通信方案解决压缩注意力在 CP 下的挑战：第一阶段交换和压缩 KV 条目，第二阶段通过 all-gather 收集所有 CP rank 上的压缩 KV 条目。

3.5.4 扩展自动微分支持张量级 Activation Checkpointing

实现了张量级的 activation checkpointing 机制，开发者只需实现前向传播并标注需要 checkpoint 的张量。框架利用 TorchFX 追踪计算图，自动识别最小重计算子图。

3.6 推理框架

3.6.1 KV 缓存结构与管理

Figure 6 | DeepSeek-V4 的 KV 缓存布局。KV 缓存分为两个主要组件：CSA/HCA 的经典 KV 缓存，以及 SWA 和未就绪压缩 token 的状态缓存。

混合注意力机制引入了多种不同尺寸和更新规则的 KV 条目类型。DeepSeek-V4 设计了异构 KV 缓存布局，包含状态缓存（SWA KV 和未压缩 KV 状态）和经典 KV 缓存（CSA 和 HCA 压缩 KV）。

3.6.2 磁盘 KV 缓存存储

利用磁盘 KV 缓存消除共享前缀请求的重复 prefill。针对 SWA KV 条目提出三种管理策略：

  • 全量 SWA 缓存：存储所有 token 的 SWA KV 条目，零计算冗余
  • 周期性 Checkpoint：每 p 个 token checkpoint 一次，提供存储与计算的可调平衡
  • 零 SWA 缓存：不存储任何 SWA KV 条目，通过重计算最后 nwin·L 个 token 恢复

4. 预训练

4.1 数据构建

在 DeepSeek-V3 预训练数据基础上，构建了更多样、更高质量、更长有效上下文的训练语料。预训练语料超过 32T token，包含数学内容、代码、网页、长文档等高质量类别。

关键改进包括：针对网络数据实施过滤策略移除批量自动生成和模板化内容；中间训练阶段加入 agentic 数据增强编码能力；为多语言数据构建更大语料；特别强调长文档数据的策展。

4.2.3 缓解训练不稳定性

训练万亿参数 MoE 模型面临显著的稳定性挑战。DeepSeek-V4 发现两种有效的实用技术：

预见性路由 (Anticipatory Routing)：将骨干网络和路由网络的同步更新解耦。在步骤 t，使用当前参数 θt 进行特征计算，但路由索引使用历史参数 θt-Δt 计算。当检测到 loss spike 时自动触发短暂回滚并激活该机制。wall-time 开销约 20%。
SwiGLU Clamping：将 SwiGLU 的线性分量钳位到 [−10, 10]，门控分量上限钳位到 10。有效消除异常值并稳定训练过程。

  • DeepSeek-V4-Pro-Base 在几乎所有类别上展现压倒性优势，成为 DeepSeek 系列最强基础模型

5. 后训练

5.1 后训练流水线

后训练流水线主要沿用 DeepSeek-V3.2 的方法，但做了一项关键替换：混合强化学习 (RL) 阶段被完全替换为策略上蒸馏 (On-Policy Distillation, OPD)。

后训练采用两阶段范式：

  1. 专家独立培养：针对各目标领域（数学、编程、Agent、指令遵循等）独立训练专家模型，先 SFT 后 GRPO 强化学习
  2. OPD 统一整合：通过多教师策略上蒸馏将所有专家能力整合到单一统一模型中

5.1.2 策略上蒸馏 (OPD)

训练完多个领域专家后，采用多教师策略上蒸馏 (OPD) 将专家能力整合到最终模型。给定 N 个专家模型 {πE₁, ..., πE_N}，OPD 目标函数为：

LOPD(θ) = Σi=1N wi · DKL(πθ ‖ πE_i)

其中 wi 是各专家的分配权重。通过计算反向 KL 损失 DKL(πθ ‖ πE_i)，学生模型在自身生成的轨迹上学习教师的输出分布。DeepSeek-V4 采用全词汇表 logit 蒸馏而非 token 级 KL 估计，获得更稳定的梯度估计和更忠实的知识蒸馏。

5.2 RL 和 OPD 基础设施

  • FP4 量化集成：所有推理和 rollout 阶段使用原生 FP4 权重加速
  • 高效教师调度：教师权重卸载到集中式分布式存储，按需加载；仅缓存最后一层隐状态而非全词汇表 logit
  • 可抢占和容错 Rollout 服务：实现 token 粒度的 Write-Ahead Log (WAL)，支持抢占后恢复
  • 百万 Token 上下文 RL 扩展：数据格式分解为轻量级元数据和重型 per-token 字段，通过共享内存数据加载器消除节点内数据冗余
  • DSec 沙箱基础设施：基于 Rust 构建的生产级沙箱平台，支持 Function Call、Container、microVM、fullVM 四种执行基底

6. 结论、局限性与未来方向

DeepSeek-V4 系列通过结合 CSA 和 HCA 的混合注意力架构，打破了超长上下文处理的效率壁垒。架构创新加上广泛的基础设施优化，实现了百万 token 上下文的高效原生支持，为未来的测试时扩展、长期任务和在线学习等新兴范式奠定了基础。

核心成就：
  • DeepSeek-V4-Pro-Max 重新定义了开源模型的最优水平
  • 在知识 benchmark 上大幅超越先前开源模型
  • 推理性能接近前沿闭源模型
  • Agent 能力具有竞争力
  • DeepSeek-V4-Flash-Max 以高性价比架构达到与领先闭源模型可比的推理性能
局限性与未来方向：
  • 为追求极致长上下文效率，架构中保留了许多初步验证的组件和技巧，使架构相对复杂。未来将精简到最核心设计
  • 预见性路由和 SwiGLU Clamping 虽有效缓解训练不稳定性，但底层原理尚未充分理解
  • 将积极探索模型稀疏性的新维度（如稀疏嵌入模块）
  • 持续研究低延迟架构和系统技术
  • 正在整合多模态能力
  • 致力于更好的数据策展和合成策略
