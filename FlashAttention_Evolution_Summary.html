零、引言：一条贯穿四代的主线

FlashAttention 系列是近五年来 GPU 上精确注意力（exact attention）加速的里程碑工作， 由 Tri Dao 等人持续迭代。这四篇论文的演化并非简单的"性能优化"，而是一场 硬件-算法协同设计的教科书——每一代都精准地回应了当代 GPU 架构的新瓶颈。

一条核心主线： "注意力的瓶颈不在算力，而在 IO；而 IO 的形态随硬件演化而不断变化"。 FA-1 解决 HBM ↔ SRAM 的数据搬运；FA-2 解决 SRAM 内部的 warp 间通信； FA-3 解决异步执行单元的同步开销；FA-4 解决 Tensor Core 之外的"次级单元"（SMEM、指数单元）瓶颈。 每一代都在问："当前硬件的下一个瓶颈在哪里？"

一、FlashAttention（2022）：IO 感知的精确注意力基础

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness

Dao et al., NeurIPS 2022 Stanford University A100 GPU 精确非近似

1.1 核心问题：标准注意力的 IO 瓶颈

标准 PyTorch 注意力实现的问题不在 FLOPs，而在显存访问。给定 Q, K, V ∈ RN×d：

S = QKT ∈ RN×N  →  写 HBM
P = softmax(S) ∈ RN×N  →  读 S + 写 P 到 HBM
O = PV ∈ RN×d  →  读 P + 写 O 到 HBM

这种实现需要物化 N×N 注意力矩阵到 HBM，导致 O(N²) 的内存占用和大量的 HBM 读写。 而 softmax、mask、dropout 等 elementwise 操作都是内存受限（memory-bound）的， 实际耗时远超 matmul 本身。

图 1：FlashAttention 核心架构。左：GPU 内存层次——SRAM（19 TB/s, 20 MB）远快于 HBM（1.5 TB/s, 40 GB），但容量小得多； 中：Tiling 算法——外循环遍历 K/V 块，内循环遍历 Q 块，在 SRAM 内计算后直接写回 HBM，不物化 N×N 矩阵； 右：GPT-2 上 PyTorch 标准注意力 vs FlashAttention 的耗时对比，后者通过融合单一 kernel 实现 7.6× 加速。

1.2 两大核心技术

(1) Tiling（分块）+ Online Softmax

Tiling 的关键挑战是：softmax 需要"全局行最大值"和"全局行求和"来保证数值稳定， 而分块计算每次只看到一部分。Online Softmax（Milakov & Gimelshein, 2018） 通过维护运行中的最大值 m 和归一化因子 ℓ，在分块遍历过程中渐进式地纠正之前的结果：

mnew = max(mold, rowmax(S(j)))
ℓnew = emold−mnew ℓold + rowsum(eS(j)−mnew)
Onew = diag(ℓnew)−1(diag(ℓold) emold−mnew Oold + eS(j)−mnewV(j))

当遇到更大的 max 值时，通过 exp 差值追溯修正之前累积的 O 和 ℓ。 数学上与完整 softmax 等价——这是"精确"（exact）的关键。

(2) Recomputation（反向传播重计算）

传统做法需要在前向时保存 S 和 P（O(N²) 内存）以供反向传播。FA1 只保存 (m, ℓ) 行统计量（O(N) 内存），反向传播时在 SRAM 内重新计算 S、P。 虽然增加了 FLOPs，但由于 HBM 访问大幅减少，反向传播反而更快。 这是"用计算换 IO"的典型设计。

1.3 IO 复杂度分析（FA1 理论贡献）

标准注意力 HBM 访问：Θ(Nd + N²)
FlashAttention HBM 访问：Θ(N²d² M−1)   (M = SRAM 大小)

对于典型值 d=64-128, M≈100 KB，d² 远小于 M，所以 FA1 的 HBM 访问量远少于标准实现。 论文还证明了这是渐近最优的——不存在任何精确算法能在所有 SRAM 大小下 更少的 HBM 访问。

图 2：(左) 块大小的影响——更大的块减少 HBM 访问，但受限于 SRAM 容量； (右) 块稀疏 FlashAttention——稀疏性与加速比成正比。

1.4 实验结果（A100）

  • BERT-large：比 MLPerf 1.1 记录快 15%（17.4 vs 20.0 分钟）
  • GPT-2：比 HuggingFace 快 3×、比 Megatron-LM 快 1.7×
  • 长序列（1K-4K）：Long-Range Arena 快 2.4×
  • 能力解锁：首次在 Path-X (16K)、Path-256 (64K) 上取得 better-than-chance 性能
  • 内存：从 O(N²) 降为 O(N)，GPT-2 上节省 10-20× 内存
FA1 的历史意义：它证明了"精确注意力也可以显著加速"——不需要像 Linformer、Performer 那样 用近似牺牲质量。这改变了整个领域的方向——后续长序列工作几乎都建立在 FA 之上，而非近似方法。

二、FlashAttention-2（2023）：更好的并行化与工作分区

FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning

Tri Dao, 2023.07 A100 / H100 精确非近似 2-4× faster than FA1

2.1 问题：FA1 为什么只达到 25-40% 峰值？

FA1 虽然通过减少 HBM 访问获得了显著加速，但仍然远低于 GEMM 的极限—— FA1 只达到 A100 FP16 理论峰值的 25-40%，而优化的 GEMM 能达到 80-90%。 Tri Dao 通过 profiling 发现三个主要问题：

  1. 非 matmul FLOPs 太多：A100 上 matmul 吞吐 312 TFLOPS，但非 matmul (FP32 普通浮点) 只有 19.5 TFLOPS——相差 16 倍。 FA1 的每步 Online Softmax 都要做 diag(ℓ)−1 这样的 rescale，这些非 matmul 操作占比过大。
  2. 并行度不足：FA1 只在 batch 和 head 维度并行。当 batch 很小或序列很长时，SM 利用率低。
  3. Warp 间通信浪费：FA1 的 "split-K" warp 分区需要 warp 间通过共享内存通信中间结果。

2.2 三大改进

改进 1：减少非 matmul FLOPs（Online Softmax 改写）

FA1 每步都对 output 做 diag(ℓ)−1 归一化。FA2 发现： 可以维护一个"未归一化"的 Õ，最后再做一次归一化。

FA1: O(2) = diag(ℓ(1)/ℓ(2))−1 O(1) + diag(ℓ(2))−1 eS(2)−m(2)V(2)

FA2: Õ(2) = diag(em(1)−m(2)) Õ(1) + eS(2)−m(2)V(2)
最后：O = diag(ℓ(last))−1 Õ(last)

同时，反向传播时只需保存 L = m + log(ℓ)，而不需要同时保存 m 和 ℓ。

图 3：FA2 的 Online Softmax 图示——将 K 分为两块，分别计算本地注意力， 最后通过 rescaling 合并成正确的全局 softmax 输出。

改进 2：序列维度上的并行（关键突破）

FA1 的外循环是 K/V 块，内循环是 Q 块——这意味着不同 Q 块之间有依赖（共享同一个 output）， 无法直接并行。FA2 交换内外循环：外循环改为 Q 块，内循环为 K/V 块。

为什么这个改变很重要？交换后，每个 Q 块的计算完全独立—— 可以分配给不同的 thread block（SM）并行执行。这意味着： (1) 前向传播在序列长度上"embarrassingly parallel"； (2) 小 batch 长序列场景下，SM 利用率大幅提升。

此思路最初由 Phil Tillet 在 Triton 实现中提出，FA2 将其吸收到 CUDA 实现中。

图 4：FA2 并行化方案。前向传播每个 worker 负责一个 Q 行块（完全独立）； 反向传播每个 worker 负责一个 K/V 列块，通过 atomic add 更新 dQ。

改进 3：warp 间工作分区优化

FA1 采用 "split-K" 方案：4 个 warp 分别持有 K 的不同部分，所有 warp 共享 Q。 每个 warp 计算部分 QKT，然后需要通过共享内存同步和累加中间结果。

FA2 反其道而行：分 Q 而非分 K。每个 warp 持有 Q 的不同行块，共享 K、V。 每个 warp 独立计算自己的 output slice，不需要 warp 间通信。

图 5：Warp 分区对比。左：FA1 "split-K"——4 个 warp 分 K，共享 Q，需要 warp 间同步； 右：FA2 "split-Q"——4 个 warp 分 Q，共享 K/V，每个 warp 独立写出自己的 output，无需 warp 间通信。

2.3 实验结果

图 6：A100 上的前向+反向速度。FA2 (紫色) 在所有设置下都显著超越 FA1 和 xformers， 头维度 128、16K 序列时达到 ~200 TFLOPS（FA1 的 ~2×）。
  • 峰值性能：230 TFLOPS（A100 理论峰值的 73%），比 FA1 快 2×
  • 端到端训练：GPT-style 模型达到 225 TFLOPS/A100（72% MFU），比 FA1 快 1.3×
  • H100 上：不改代码直接跑达到 335 TFLOPS（尚未使用 H100 的 TMA / WGMMA / FP8 新特性）
FA2 的哲学："让所有时间都花在 matmul 上"。通过精细的非 matmul FLOPs 优化、 序列维度并行、以及重新设计的 warp 工作分区，FA2 成功地把注意力从"部分内存受限"转变为 "接近 matmul 的计算受限"。

三、FlashAttention-3（2024）：异步与低精度

FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision

Shah, Bikshandi, Zhang, Thakkar, Ramani, Dao · 2024.07 Colfax / Meta / NVIDIA / Princeton / Together AI H100 (Hopper) FP16 / FP8

3.1 问题：H100 上 FA2 只有 35% 利用率

FA2 直接移植到 H100 时只能达到 35% 的利用率，远低于 GEMM 的 80-90%。原因是 H100 引入了 根本性的新硬件特性，而 FA2 的同步设计无法利用：

  • Tensor Memory Accelerator (TMA)：异步 HBM ↔ SMEM 数据搬运，不占用 CUDA cores
  • WGMMA (warpgroup MMA)：异步 warpgroup 级 matmul，可以从 SMEM 直接读数据
  • FP8 Tensor Core：FP8 throughput 是 FP16 的 2×，但需要特殊的数据布局
  • Thread block clusters：多个 CTA 可以协同（DSMEM）

3.2 三大核心技术

技术 1：Producer-Consumer 异步 + Warp Specialization

传统 CUDA kernel 所有 warp 执行相同的代码路径，但 H100 的异步单元让 "不同 warp 做不同的事"成为可能。FA3 将一个 CTA 的 warpgroups 分为两类：

P

Producer warpgroup

专门负责发起 TMA 指令，从 HBM 异步加载 Q, K, V 到共享内存的循环 buffer。 不做任何计算。由于只需要一个线程发起 TMA，producer 可以释放大部分寄存器给 consumer 使用。

C

Consumer warpgroup

专门负责执行 WGMMA 矩阵乘、softmax 和输出更新。从循环 buffer 等待新数据到达， 计算完后释放 buffer 给 producer。占用更多的寄存器以加速计算。

这种"生产者-消费者"范式让数据加载和计算可以完全重叠—— 当 consumer 在处理第 j 块时，producer 已经在加载第 j+1 块。

技术 2：Pingpong Scheduling — 在 warpgroup 间重叠 GEMM 和 Softmax

在一个 warpgroup 内部，softmax 和 GEMM 是顺序执行的（softmax 依赖前一个 GEMM 的输出，后一个 GEMM 依赖 softmax）。 FA3 用两个 consumer warpgroup "乒乓调度"：

图 7：Pingpong 调度。Warpgroup 1 做 softmax 时，warpgroup 2 的 Tensor Core 正在做 GEMM； 然后角色互换。这把 softmax 的时间"藏"在 GEMM 的阴影中。
为什么 pingpong 有效？H100 上 FP16 matmul 有 989 TFLOPS，但特殊函数（exp）只有 3.9 TFLOPS—— matmul 比 exp 快 256 倍。如果串行执行，exp 会占满 50% 的时间。 但 exp 在独立的 MUFU（multi-function unit）上执行，可以与 Tensor Core 并行——pingpong 正是利用了这一点。 实测从 570 TFLOPS 提升到 620-640 TFLOPS。

技术 3：Intra-Warpgroup 的 2-stage GEMM-Softmax Pipeline

即使在一个 warpgroup 内，也可以跨迭代流水线化 GEMM 和 softmax。

图 8：2-stage GEMM-Softmax 流水线。第 j 迭代的 softmax 与第 j+1 迭代的 GEMM0 (QKT) 并行执行；同时第 j−1 迭代的 GEMM1 (PV) 也在进行。代价是额外的寄存器存储中间 S 矩阵。

技术 4：FP8 低精度 + Block Quantization + Incoherent Processing

直接用 FP8 Tensor Core 能翻倍吞吐，但面临两个问题：

  1. Layout 问题：WGMMA FP8 要求两个操作数都是 k-major，但 V 天然是 mn-major。 解决方案：用 in-kernel transpose（LDSM/STSM 指令）动态转置 V。
  2. 精度问题：FP8 (e4m3) 只有 3 位尾数，LLM 常有 outlier 激活，per-tensor scaling 误差大。 FA3 采用两种技术：
    • Block Quantization：每个块独立的 scale，融合到 rotary embedding 中零开销。
    • Incoherent Processing：用随机 Hadamard 矩阵 M 变换 Q 和 K （QM 和 KM），由于 MMT = I，不改变 attention 输出， 但把 outlier "分散"到所有维度，减少量化误差。

3.3 实验结果（H100）

图 9：H100 上的前向速度。FA3 (紫色) 在所有头维度和序列长度下都显著超越 FA2 和 cuDNN。 head dim 128、16K 序列时达到 ~650 TFLOPS。对于 head dim 256，FA3 在 cuDNN 之前就已经是 state-of-the-art。
图 10：FP8 前向速度（head dim 256）。FA3 达到 接近 1.2 PFLOPS/s——FP16 的 1.5× 以上。

FA3 的意义：证明了"新硬件特性必须被算法显式利用"——简单移植只能达到 35% 利用率， 而通过 warp specialization + pingpong + FP8 协同设计，可以达到 75%。 同时 incoherent processing 这一纯线性代数技巧，让 FP8 的精度损失降到可接受水平。

四、FlashAttention-4（2026）：Blackwell 的非对称瓶颈

FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling

Zadouri, Hoehnerbach, Shah, Liu, Thakkar, Dao · 2026.03 Princeton / Meta / Colfax / NVIDIA B200 (Blackwell) CuTe-DSL

4.1 问题：硬件的"非对称扩展"

B200 相比 H100 看似全面升级，但仔细看会发现各硬件单元的扩展速度不均匀：

硬件单元H100B200扩展比
Tensor Core (BF16 MMA)1 PFLOPS2.25 PFLOPS2.25×
共享内存带宽~128 B/cycle~128 B/cycle1.0× (不变)
指数函数单元 (MUFU)16 ops/clock/SM16 ops/clock/SM1.0× (不变)
新特性WGMMA + TMA+ TMEM (256 KB/SM) + 2-CTA MMA + 128×128 tiles—
瓶颈转移：当 Tensor Core 翻倍而其他单元不变时，"瓶颈"从 matmul 转移到 shared memory 带宽和指数函数单元。FA4 的 roofline 分析显示， 在 B200 上，SMEM 流量和 exp 操作共同主导了 attention 执行时间， 超过 MMA 25-60%。简单移植 FA3 会留下大量性能未被挖掘。

4.2 Blackwell 的新硬件特性

1

Tensor Memory (TMEM)

每 SM 额外 256 KB 的片上内存，专门用于 存储 Tensor Core 的累加器。 Hopper 的累加器在寄存器中，造成严重寄存器压力；Blackwell 的 TMEM 释放了寄存器， 允许更大的 tile size。

2

2-CTA MMA Mode

两个 CTA 协同执行一个 MMA 指令：一个 CTA 初始化 MMA，另一个必须保持活跃。 每个 CTA 只存一半的 operand B，通过 DSMEM 共享——有效减少 SMEM 容量压力。 支持 M=128 或 256 的更大 tile。

3

128×128 MMA Tiles

从 Hopper 的 64×128 扩大一倍。更大的 tile = 更好的数据复用 = 更少的 SMEM 流量， 但要求更多的 TMEM/寄存器来容纳累加器。

4

完全异步 MMA

Blackwell MMA 直接写入 TMEM 异步返回，不阻塞寄存器回写。 这使得计算与其他操作可以更深度重叠。

4.3 四大算法创新

创新 1：为 2-CTA + TMEM 重新设计的流水线

图 11：FA4 前向流水线。4 个 SM 协同处理 8 个 Q tile (CTA 0-3 各处理 2 个)。 Tensor Core 和 MUFU 在时间轴上完美交错——MUFU 在做 exp 时 Tensor Core 在算下一个 QKT。 每个 GEMM 需 512 cycles，每个 exp 需 1024 cycles——exp 需要两倍的时间，因此成为关键路径。

创新 2：指数函数的软件模拟（解决 exp 瓶颈）

B200 上 MUFU 只提供 16 ops/clock/SM，而 MMA 有 8192 ops/clock/SM——差距 512 倍。 FA4 的巧妙解法：用 FMA 单元（FP 乘加）软件模拟 2x， 与 MUFU 并行运行，把 exp 吞吐翻倍。

2x = 2⌊x⌋ · 2x−⌊x⌋

整数部分 2⌊x⌋ 通过 IEEE 754 位操作（移位到 exponent 字段）计算； 小数部分 2xfrac 用 3-5 阶多项式近似（Horner 求值 + FMA）。 3 阶多项式的误差 8.8×10−5——在 BF16 量化误差（3.9×10−3）面前完全可以忽略。

部分模拟策略：实际只对 10-25% 的 softmax 条目做软件模拟，剩余仍走 MUFU。 这样寄存器压力不会爆炸，同时 exp 吞吐得到提升。比例根据 MMA 和 exp 吞吐的经验比调整。

创新 3：条件化 Softmax Rescaling

Online softmax 每次遇到新的 max 都要对之前的 O 做 rescale（一次额外的向量乘法）。 FA4 观察到：可以容忍小的"slack"——当 mj − mj−1 ≤ τ（典型 τ=log₂(256)=8）时 跳过 rescale，直接累加：

Oj = emj−1−mj Oj−1 + eSj−mj Vj   如果 mj − mj−1 > τ
Oj = Oj−1 + eSj−mj−1 Vj   否则

最终的归一化步骤会修正所有累积的小误差，数值精度不受影响。 这大幅减少了向量操作的频率。

创新 4：2-CTA 的反向传播（halving atomics）

图 12：2-CTA 反向传播中的 dQ 计算。两个 CTA 通过 DSMEM 交换一半的 dS， 每个 CTA 形成 (M/2 × 2N) 的 operand，独立计算各自的 dQ 累加。 这将全局 atomic add 的次数减半，因为每个 CTA 只写 dQ 的一半。

反向传播有 5 个 GEMM，shared memory 流量比前向大。FA4 在反向使用 M=256, N=128 的 tile （在 2-CTA 模式下），让 operand B 的 SMEM 读取减半。同时通过 DSMEM 交换 dS， 将每个 CTA 的 dQ 累加 operand 形成 (M/2, 2N) 的形状，自然地把 atomic 次数减半。

4.4 CuTe-DSL：Python 内嵌的 DSL

FA4 的另一个重大变化是完全用 Python 中的 CuTe-DSL 实现， 而非 CUDA C++。优点：

  • 编译速度提升 20-30×：单 kernel 编译从 55 秒（FA3 C++）降到 2.5 秒
  • 保持 C++ 模板元编程的全部表达力：可以直接写 PTX escape hatch
  • 更快的迭代：研究者无需深厚 C++ 模板经验即可贡献新的注意力变体

4.5 实验结果（B200）

4.6 额外特性

a

Deterministic Backward

原子加导致的非确定性一直是训练调试的痛点。FA4 提供确定性反向传播模式—— 用 semaphore 串行化 global 原子 reduction，通过 batch/head swizzling 减少 stall。 达到非确定性版本 75% 的速度。

b

LPT (Longest-Processing-Time) 调度

Causal 或变长序列会造成负载不均衡。FA4 使用 LPT 调度器—— 先处理长的 worktile，让短的填充 tail。Causal 情况下获得 4-14% 额外收益。

FA4 的哲学："当硬件非对称扩展时，瓶颈不再在最显眼的地方"。 当 Tensor Core 翻倍时，SMEM 带宽和 exp 单元成为新瓶颈——FA4 的每个优化都是在 绕过或分担这些次级资源。软件模拟 exp、条件化 rescale、2-CTA 共享 operand—— 这些都是典型的"硬件 roofline 倒推算法设计"的例子。

5.3 关键洞察

1

每代都重新识别瓶颈

FA 系列从不"在已有优化上再优化"——每一代都从 roofline 分析重新出发， 找出新架构下的下一个瓶颈（IO → 非matmul → 同步 → SMEM/exp）。

2

精确算法优于近似

FA 系列一直坚持"exact attention"——数学上与标准注意力等价。 这反证了 Linformer/Performer 等近似路线的多数结论（性能损失不可接受）， 使得 FA 成为 Transformer 训练的事实标准。

3

算法-硬件协同设计

FA 系列的每个优化都需要深入理解硬件： FA1 的 SRAM/HBM、FA2 的 warp 分区、FA3 的 TMA/WGMMA、FA4 的 TMEM/2-CTA。 这已经不是"算法研究"而是"协同系统研究"。

4

Online Softmax 是贯穿四代的核心

数学本质从未改变：Online Softmax + Tiling。 所有变化都是"如何在不同硬件上高效实现这个核心"—— 这个核心是整个 FA 系列的"genetic code"。

六、结论与影响

FlashAttention 系列是硬件感知算法设计的典范。 四篇论文跨越 4 年、3 代 GPU 架构（Ampere → Hopper → Blackwell）， 每一代都精准地解决当代硬件的特有瓶颈：

  1. FA1 识别出"注意力的瓶颈是 IO 而非 FLOPs"，用 tiling + online softmax 把 HBM 访问从 O(N²) 降为 O(N²·d²/M)，是精确注意力加速的"零到一"。
  2. FA2 把并行度从 "batch × head" 扩展到 "batch × head × seq_len"，同时精简非 matmul 运算，让 A100 达到 73% 利用率。
  3. FA3 用 warp specialization、pingpong、2-stage pipeline 榨取 H100 的异步特性，加上 block quantization + incoherent processing 让 FP8 精度可用。
  4. FA4 在 Blackwell 的非对称扩展（Tensor Core 翻倍、SMEM/exp 不变）下，通过 TMEM/2-CTA、软件模拟 exp、条件 rescale 等手段解决新瓶颈。
对行业的影响： FlashAttention 系列已成为所有主流 LLM 训练和推理框架的默认实现—— PyTorch (torch.nn.functional.scaled_dot_product_attention)、 vLLM、SGLang、TensorRT-LLM、Megatron-LM 等都深度集成。 可以说：没有 FA 系列，就没有今天的长上下文 LLM。 从 GPT-4 的 32K 到 Gemini 的 1M，每个长上下文模型背后都是 FA 系列的 kernel 在支撑。

未来方向：随着 B300/GB300 进一步提升 exp 吞吐（16→32 ops/clock/SM）， 以及 FP4 量化（SageAttention 3 等）的成熟， FA5 很可能需要重新审视"softmax 是否还需要精确计算"、 "低秩与稀疏是否可以重新进入精确范式"这类更深层问题。
